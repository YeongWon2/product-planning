# manyfast 기능 선별

> manyfast 기능 중 코드 밖의 기획만 남기고, 로컬·한 문장 원칙으로 다시 만든다.

## 가져간다

### 시작
- **아이디어 입구**: 한 줄 아이디어로 새 기획을 시작한다.
- **자료 입구**: PDF·문서·회의록 파일을 읽어 사실만 옮긴다.
- **변경 입구**: 기존 doc.md에서 바꿀 줄과 영향받는 줄만 다룬다.

### 인터뷰
- **질문 카드**: 한 번에 최대 3개를 선택지·추천·직접 입력으로 묻는다.
- **자료 요약**: 자료에서 확인된 것과 없는 것을 먼저 3줄로 보여 준다.
- **미정 보관**: 답 없는 항목은 열린 질문으로 문서에 남긴다.

### 문서
- **생성 순서**: 정의 → 도메인 스토리 → 유저플로우 → 와이어프레임 → 정책 순으로 채운다.
- **완성도**: 채운 섹션과 남은 질문 수를 퍼센트로 보여 준다.
- **변경 제안**: AI 수정은 줄 단위 카드로 승인·거절·일괄 승인한다.
- **영향 연결**: 한 줄을 바꾸면 이름이 같은 다른 섹션 줄을 함께 표시한다.

### 유저플로우
- **섹션 묶음**: 흐름을 역할·단계별 섹션으로 나눈다.
- **노드 종류**: 화면·행동·분기·시작 네 종류만 쓴다.
- **자동 정렬**: 그림 배치는 사람이 손대지 않고 코드가 정한다.

### 와이어프레임
- **화면 자동 생성**: 유저플로우의 화면 단계마다 저해상도 화면을 그린다.
- **섹션 정렬**: 와이어프레임을 유저플로우 섹션 순서로 묶는다.
- **클릭 이동**: 단추를 누르면 플로우상 다음 화면으로 넘어간다.

### 검토
- **관점 검토**: 개발·사업·UX·디자인·QA·보안 6관점으로 빈틈을 찾는다.
- **근거 인용**: 지적마다 문서의 근거 줄과 관련 섹션을 단다.
- **처리 상태**: 지적은 해결·보류·채팅에서 해결로 닫는다.

### 회의록
- **결정 추출**: 회의록에서 결정을 확정·미정으로 나눠 뽑는다.
- **반영 제안**: 확정 결정은 바꿀 줄을 변경 제안 카드로 만든다.

### 버전
- **자동 백업**: AI가 고치기 전 상태를 자동으로 저장한다.
- **되돌리기**: 저장된 버전으로 문서를 복원한다.

### 내보내기
- **md 원본**: doc.md 자체가 결과물이자 AI 입력이다.
- **html 시각화**: md와 같은 템플릿에 흐름도·와이어프레임을 그린다.
- **Mermaid**: 유저플로우를 Mermaid로도 내보낸다.

### 설정
- **문체 규칙**: 팀 용어와 하지 말아야 할 표현을 프로젝트에 저장한다.
- **모델 선택**: Claude Code·Codex 중 작성과 검토 provider를 고른다.

## 버린다

- **기능 3계층**: 요구사항·기능·상세 계층은 코드 구조라서 쓰지 않는다.
- **동작·표시·데이터 슬롯**: 화면 동작과 데이터는 코드에서 읽을 수 있다.
- **권한·규칙·예외 슬롯**: 기능마다 두지 않고 정책 한 줄로 합친다.
- **수용·성공 기준**: 기능별 완료 조건은 테스트 코드의 몫이다.
- **항목 ID·상태·중요도**: md를 읽기 어렵게 하므로 붙이지 않는다.
- **보기 3종**: 그래프·디렉토리·도큐먼트 대신 문서 한 화면만 둔다.
- **고해상도 와이어프레임**: 디자인은 범위 밖이라 저해상도 상자만 그린다.
- **캔버스 직접 편집**: 와이어프레임은 md 한 줄을 고쳐서 바꾼다.
- **실시간 협업·멤버 권한**: 로컬 도구라서 공유는 html 파일과 git으로 한다.
- **링크 공유·만료**: 외부 호스팅을 하지 않는다.
- **크레딧·요금제**: 사용자 자신의 CLI를 쓰므로 과금이 없다.
- **엑셀·Figma 내보내기**: md와 html 외 형식은 만들지 않는다.
- **이슈 트래커 연동**: Jira·Linear·GitHub 연결은 이번 범위 밖이다.
- **그룹·휴지통·즐겨찾기**: 파일 시스템이 그 역할을 한다.

## 더 잘한다

- **한 문장 린트**: 모든 줄이 한 문장·60자 안인지 코드가 강제한다.
- **코드 흔적 차단**: 필드·API·타입 같은 코드 설명이 들어오면 막는다.
- **로컬 실행**: 데이터가 내 컴퓨터를 떠나지 않는다.
- **교차 검토**: 작성 모델과 다른 provider가 검토해 일치율을 낸다.
- **하네스 루프**: 단계 게이트와 린트 재시도를 프롬프트가 아닌 코드가 돌린다.
- **git 친화**: md 줄 단위라 변경 이력이 diff로 바로 읽힌다.
- **코드베이스 입구**: 기존 레포를 읽고 코드에 없는 정책만 묻는다.
- **구현 대조**: 구현 뒤 코드가 정책 줄을 어기는지 검사한다.

## 결정 · 열린 질문

- **앱 없음**: 혼자 쓰고 친구에게 보여 주는 정도라 웹앱 없이 CLI와 플러그인으로 만든다. (영원)
- **공유 방식**: 친구에게는 플러그인 설치 또는 doc.html 파일 하나로 공유한다. (영원)
- **코멘트 제외**: 혼자 쓰므로 코멘트 기능은 만들지 않는다. (영원)
- **MCP 제외**: 코딩 에이전트는 doc.md 파일을 직접 읽으므로 MCP 서버는 없다. (영원)
- **구현 대조는 2차**: 1차는 기획 작성까지만 하고 코드 대조는 다음에 붙인다. (추천)
