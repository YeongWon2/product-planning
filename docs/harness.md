# 하네스

> 하네스는 요구사항·PRD·SDD 스펙을 매 답마다 검토해, 무엇이 추가돼야 완성인지와 다음 단계를 알려 주는 CLI다.
> 의존성 없이 Node 20 이상에서 돈다.
> 하네스는 문서 내용을 쓰지 않는다. 읽고 세고 알려 주고, 확정된 문서만 프로젝트로 옮긴다.

---

## 1. 명령

| 명령 | 하는 일 |
|---|---|
| `node scripts/pp.mjs init <폴더> <기능 이름>` | 없는 파일만 빈 틀로 만든다 (PRD가 확정되기 전에는 `sdd.md`를 만들지 않는다) |
| `node scripts/pp.mjs check <폴더> [--json]` | 지금 단계와 완성도, 추가돼야 완성인 것, 다음 할 일을 보여 준다 |
| `node scripts/pp.mjs lock <폴더>` | 요구사항(1~4단계)이 다 갖춰졌으면 잠금 지문을 `lock.json`에 남긴다 |
| `node scripts/pp.mjs unlock <폴더>` | 잠금을 푼다. 요구사항을 고친 뒤 다시 `lock`한다 |
| `node scripts/pp.mjs sheet <폴더> [--save]` | 요구사항 대조에 쓸 검토지를 JSON으로 낸다. `--save`면 작업 폴더의 `sheet.json`에 쓴다 |
| `node scripts/pp.mjs export <폴더> <문서 폴더>` | 확정된 문서를 `<문서 폴더>/{feature}/`에 쓴다. 문서 폴더는 보통 `<프로젝트>/docs`다 (6장) |
| `node scripts/pp.mjs discard <폴더>` | 내보내지 않고 작업 폴더를 지운다 |

종료 코드는 `0` 완료, `1` 아직 남음, `2` 입력이나 경로 오류다.

---

## 2. 폴더

작업 폴더는 프로젝트 밖 `~/.product-planning/work/{feature}/`에 둔다.

```text
~/.product-planning/work/{feature}/
├─ plan.md     요구사항과 PRD (planning-guide.md)
├─ lock.json   잠근 요구사항의 지문
├─ sdd.md      개발자용 SDD 스펙 (sdd-guide.md)
├─ trace.json  모델이 쓴 요구사항 대조 (3장)
└─ sheet.json  sheet --save로 쓴 검토지 (있어도 되고 없어도 된다)
```

모두 사람이 읽을 수 있다. `check`는 아무 파일도 고치지 않고, `sheet`는 `--save`일 때 `sheet.json`만 쓴다.

---

## 3. 대조 파일

`sheet`가 내주는 검토지에는 완성 기준마다 번호, 문장, `fingerprint`가 있고, 근거 후보(`lines`)가 함께 있다.
근거 후보는 트리의 모든 줄 경로와 조건표 행(`조건표 › 조건 › 정해지는 곳`)이다. 조건표 행은 "본인만 고칠 수 있다"처럼 조건이 무엇으로 정해지는지가 기준일 때 쓴다.
모델은 검토지를 보고 `trace.json`을 아래 모양으로 쓴다.

```json
{
  "R1-1": {
    "verdict": "met",
    "evidence": ["게시글 수정 › ? 수정 권한이 있는가 › **예** › ◆ 게시글 상태 › **게시됨** › [수정] 누름 → 수정 모달이 열린다"],
    "fingerprint": "검토지의 값을 그대로"
  },
  "R1-2": {
    "verdict": "missing",
    "missing": "저장한 뒤 댓글이 어떻게 되는지 나오는 줄이 있어야 완성이다.",
    "fingerprint": "검토지의 값을 그대로"
  }
}
```

| 하네스가 보는 것 | 걸리면 |
|---|---|
| 제외되지 않은 완성 기준마다 판단이 있는가 | `[대조 없음]` |
| `fingerprint`가 지금 기준 문장과 맞는가 | `[대조 낡음]` 기준이 바뀌었으니 다시 판단한다 |
| `met`의 근거 줄이 지금 트리에 있는가 | `[대조 낡음]` 근거 줄이 바뀌었으니 다시 판단한다 |
| `met`인데 근거 줄이 없는가 | `[근거 없음]` |
| `missing`인가 | `[요구사항]` 모델이 적은 추가돼야 할 것을 그대로 보여 준다 |

완성도는 제외되지 않은 완성 기준 가운데 낡지 않은 `met`의 비율이다.

## 4. 보고 모양

```text
단계  SDD › 4. 단위별 트리
완성도  R1 1/2 · 전체 50%
추가되어야 완성
1. [빠진 상태] 게시글 수정 › ◆ 게시글 상태 아래 '삭제됨' 갈래가 없다.
2. [요구사항] R1-2 저장한 뒤 댓글이 어떻게 되는지 나오는 줄이 있어야 완성이다.
다음  위 2건을 질문으로 바꿔 사람에게 묻는다.
```

- 단계는 앞에서부터 처음으로 걸린 곳이며, 걸린 것은 그 단계의 것만 보여 준다.
- 뒤 단계에 남은 것은 `그 밖에 N건 (PRD › 7. 확정 1 · …)`처럼 단계별 건수만 알린다. `--json`의 `later`에는 단계·종류·메시지가 모두 있다.
- 막지 않는 경고는 `살펴볼 것 (막지 않는다)` 아래에 따로 보인다. 단계와 종료 코드를 바꾸지 않는다. `--json`에서는 `warnings`다.
- 걸린 것이 없으면 다음 단계로 무엇을 할지 한 줄로 알려 준다.

---

## 5. 단계 판정 순서

| 순서 | 단계 | 넘어가는 조건 |
|---|---|---|
| 1 | 요구사항 › 페르소나 | 페르소나마다 원하는 것과 행동 패턴이 있다 |
| 2 | 요구사항 › 요구사항 | 요구사항마다 누구·왜·우선순위(꼭·나중에)가 있고, 모든 페르소나가 요구사항에 쓰인다 |
| 3 | 요구사항 › 완성 기준 | 요구사항마다 완성 기준이 있고 번호가 맞다 |
| 4 | 요구사항 › 범위와 잠금 | 범위 밖이 있고(없으면 `없음`), `lock`으로 잠갔고, 잠근 뒤 바뀌지 않았다 |
| 5 | PRD › 요약과 목표 | 요약(3줄 안)과 배경(5줄 안)이 있고, 목표마다 `확인:`이 있다 |
| 6 | PRD › 정책 | 요구사항마다 정책이 1~7줄 있고, 예외는 `상황 → 처리` 모양이다 |
| 7 | PRD › 확정 | 선택 구역이 채워졌고(용어는 `용어: 뜻` 모양), 작성자가 있고, 정할 것이 비었고, 상태가 `확정`이다 |
| 8 | SDD › 1. 상태 수립 | 상태표에 행이 있다 |
| 9 | SDD › 2. 조건 수립 | 조건표에 행이 있다 |
| 10 | SDD › 3. 단위 나누기 | 모든 요구사항이 피쳐에 들어가고 진행표가 트리와 맞다 |
| 11 | SDD › 4. 단위별 트리 | 형식 검사가 0건이다 |
| 12 | SDD › 5. 요구사항 대조 | 모든 완성 기준이 낡지 않은 `met`이다 |
| 13 | SDD › 6. 확정 | 상태가 `확정`이다 |

- 잠금 지문에는 페르소나, 요구사항(누구·왜·우선순위), 완성 기준, 범위 밖만 든다. PRD 단계에서 채우는 정책·예외는 바꿔도 잠금이 깨지지 않는다.
- 문장 규칙([기획 작성법](planning-guide.md) 4장)은 `plan.md` 전체(용어는 뜻만, 참고 문서는 빼고)에 걸리며 그 줄이 속한 단계에서 보인다. SDD 트리는 한 줄 한 문장만 본다.
- 요구사항 제목·완성 기준·정책·예외에 단추, 버튼, 탭, 팝업, 모달, 화면 오른쪽 같은 화면 표현이 있으면 `[디자인 표현]` 경고를 낸다. 막지 않는 까닭은 [설계](design.md) 8장에 있다.
- 상태표가 비어 있으면 SDD를 시작하지 않은 것으로 보고 완성도를 내지 않는다.
- 7단계까지 통과하면 PRD 확정이다. 보고의 다음 줄이 export를 안내한다.

## 6. 결과물만 남기기

작업 흔적 없이 확정된 문서만 지금 체크아웃한 프로젝트에 남긴다.

```text
<문서 폴더>/{feature}/
├─ prd.md   PRD가 확정되면 생긴다
└─ sdd.md   SDD까지 끝나면 생긴다 (맨 위에 PRD 링크)
```

| 때 | `export`가 하는 일 | 작업 폴더 |
|---|---|---|
| PRD 확정 전 | 아무것도 쓰지 않고 종료 코드 2 | 그대로 |
| PRD 확정, SDD 전 | `prd.md`만 쓴다 | 남긴다 (SDD를 이어 쓸 수 있다) |
| SDD까지 완료 | `sdd.md`를 쓰고, `prd.md`가 없으면 함께 쓴다 | 지운다 (`--keep`이면 남긴다) |

- `{feature}`는 작업 폴더 이름이다.
- 이미 있는 파일이 작성일만 다르면 그대로 두고, 내용이 다르면 `--force` 없이는 덮어쓰지 않는다.
- 하네스 파일이 아닌 것이 든 폴더는 엉뚱한 폴더일 수 있으니 지우지 않는다. `.DS_Store` 같은 운영체제 파일은 무시한다.
- 결과 폴더가 작업 폴더와 겹치면(같거나 한쪽이 다른 쪽 안에 있으면) 결과물까지 지워질 수 있어 내보내지 않는다.
- 넣지 않는 것: 상태 줄, 정할 것, 진행표, `lock.json`, `trace.json`, `sheet.json`, `없음`인 선택 구역.
- PRD에 담는 것은 [기획 작성법](planning-guide.md) 6장에 있다.
