# 기획물 작성 규칙 (v2 초안)

> 기획물은 **비개발자와 개발자가 같은 문서를 읽고 같은 것을 이해**해야 한다.
> 검사 스크립트는 이 규칙 중 기계로 셀 수 있는 것을 잡아 질문지나 수정 대상으로 보낸다. (검사) 표시가 그런 규칙이다.

---

## 1. 쓰지 않는 것

| 규칙 | 나쁜 예 | 좋은 예 |
|---|---|---|
| 기술 용어를 쓰지 않는다 (검사) | 서버가 403을 반환한다 | 권한이 없다고 안내한다 |
| 상태 코드값을 쓰지 않는다 (검사) | `IN_PROGRESS` | 진행 중 |
| 모호어를 쓰지 않는다: 등, 적절히, 필요 시, 가능하면, 대략, 일부 (검사) | 필요 시 알림을 보낸다 | 과제 시작일에 알림을 보낸다 |
| 범위 없는 크기 표현을 쓰지 않는다 (검사) | 제목은 짧게 | 제목은 2자 ~ 50자 |
| 요구사항에 없는 내용을 쓰지 않는다 | (요청에 없던 알림 설정 화면 추가) | — |

## 2. 문장

- "누가 · 어디서 · 무엇을 하면 · 무엇이 보인다" 순서로 쓴다.
  예: "코치가 목표 관리에서 **팀 목표 설정**을 누르면 설정 팝업이 열린다."
- 한 문장에 한 가지 동작만 쓴다.
- 주어를 생략하지 않는다. "저장하면"이 아니라 "코치가 저장하면".
- 부정 조건은 무엇이 일어나는지로 쓴다. "버튼이 안 된다"가 아니라 "버튼을 보여주지 않는다" 또는 "버튼이 비활성이다".

## 3. 용어

- 용어는 `_shared/용어집.md`에 있어야 쓸 수 있다 (검사).
- 같은 대상에는 같은 단어만 쓴다. '예정'과 '진행 전'을 섞지 않는다 (검사: 용어집의 금지 동의어).
- 앱마다 표기가 다르면 용어집에 앱별 표기를 적는다.

## 4. 화면 문구

- 사용자에게 보이는 문구는 **굵게** 쓰고, 그 문구가 디자인과 개발의 원문이다.
- 변하는 값은 `{날짜}`, `{N}`처럼 중괄호로 쓰고, 무엇이 들어가는지 바로 옆에 적는다.
- 여러 기능에서 같은 상황(통신 실패, 불러오기 실패 등)은 `_shared/공통-문구.md`의 문구를 그대로 쓴다.

## 5. 표 · 그림 · 문장 나누기

| 담을 것 | 형식 |
|---|---|
| 정확한 값 (범위, 선택지, 권한, 상태) | 표 |
| 흐름과 갈래 | mermaid 그림 |
| 이유, 맥락 | 짧은 문장 |

같은 사실을 표와 문장에 두 번 쓰지 않는다. 쪼갠 문서에 공통 표를 발췌할 때는 원본 표의 행을 그대로 옮긴다.

## 6. 문서마다 지킬 것

- 문서 맨 위에 무엇을 다루는 문서인지 한 줄로 적는다.
- 쪼갠 문서는 그 문서 하나만 열어도 이해되도록 관련 요구사항, 권한 행, 상태 행을 함께 담는다.
- 문서 안에 열린 질문이 남아 있으면 그 자리에 `[질문 Q-012]`를 표시한다. 핸드오프 전에는 0개여야 한다 (검사).
