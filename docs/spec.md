# planbot

> 2D 캐릭터 기획 팀이 내 할 일로 회의하고 논의해 한 문장 기획서를 가져오면 나는 컨펌만 한다.

## 문제

- **긴 기획서**: 문장이 길고 코드 설명이 섞인 기획서는 아무도 읽지 않는다.
- **혼자 기획**: 혼자서는 사업·UX·QA·보안 관점을 한 번에 챙기기 어렵다.
- **세션 충돌**: 메인 Claude Code의 플러그인과 훅이 기획 작업에 섞여 든다.

## 목표 지표

- **회의와 컨펌만**: 기획자는 문장을 직접 쓰지 않고 회의 답변과 컨펌만 한다.
- **줄 길이**: 기획서의 모든 줄이 60자 안에 든다.
- **완성 시간**: 할 일 한 줄에서 HTML 기획서까지 30분 안에 끝난다.

## 사용자 역할

- **기획자**: 할 일을 맡기고 회의에서 답하고 결과물을 컨펌한다.
- **PM**: 회의를 열고 카드를 나누고 기획자와 팀을 잇는 유일한 창구다.
- **스토리텔러**: 사용자 역할과 도메인 스토리를 맡는다.
- **UX 설계자**: 유저플로우를 맡는다.
- **화면 담당**: 플로우 단계별 와이어프레임을 맡는다.
- **정책 담당**: 정책과 하지 않는 것을 맡는다.
- **검토단**: 다른 AI로 여섯 관점에서 초안의 빈틈을 지적한다.
- **서기**: 회의를 요약하고 문장을 검사하고 기획서를 만든다.
- **친구**: 받은 HTML 파일로 기획서를 본다.

## 도메인 스토리

1. 기획자가 PM에게 할 일을 맡긴다.
2. PM이 기획자와 요구사항 회의를 연다.
3. 서기가 회의에서 정해진 것을 요약한다.
4. PM이 확정된 요구사항을 칸반 카드로 나눈다.
5. 스토리텔러·UX 설계자·화면 담당·정책 담당이 팀 논의를 한다.
6. 검토단이 초안의 빈틈을 지적한다.
7. PM이 빠진 요구사항으로 기획자에게 재회의를 요청한다.
8. PM이 결과물을 기획자에게 보고한다.
9. 기획자가 결과물을 승인하거나 반려한다.
10. PM이 팀이 배운 것을 기획자에게 제안한다.
11. 서기가 승인된 기획서를 HTML로 만든다.
12. 친구가 HTML로 기획서를 본다.

## 유저플로우

### 설치와 시작

- **첫 실행**: 프로그램 실행 → 설정이 있나? 예: 사무실 화면 / 아니오: 온보딩
- **온보딩**: 온보딩 → [AI 연결 확인] → 연결 성공? 예: 사무실 화면 / 아니오: 온보딩
- **기획 전환**: 사무실 화면 → [기획 목록 열기] → 기획 목록 → [기획 열기] → 사무실 화면

### 기획 진행

- **할 일 맡기기**: 사무실 화면 → [할 일 입력] → 요구사항 회의
- **요구사항 회의**: 요구사항 회의 → [답하기] → 안건이 남았나? 예: 요구사항 회의 / 아니오: 칸반 보드
- **팀 논의**: 칸반 보드 → 빠진 요구사항? 예: 재회의 요청 / 아니오: 결과물 보고
- **재회의**: 재회의 요청 → [회의 수락] → 요구사항 회의
- **지켜보기**: 사무실 화면 → [캐릭터 클릭] → 캐릭터 패널

### 컨펌과 학습

- **컨펌**: 결과물 보고 → 승인하나? 예: 문서 보기 / 아니오: 반려 사유 입력
- **반려**: 반려 사유 입력 → [반려] → 칸반 보드
- **학습**: 배운 것 제안 → 기억할까? 예: 배운 것 목록 / 아니오: 사무실 화면
- **학습 관리**: 사무실 화면 → [배운 것 보기] → 배운 것 목록

### 결과와 관리

- **열람**: 문서 보기 → [플로우 단계] → 와이어프레임 보기
- **공유**: 문서 보기 → [HTML 내보내기] → 파일 저장
- **기록**: 사무실 화면 → [타임라인] → 타임라인
- **설정**: 사무실 화면 → [설정] → 설정 화면

- **배운 것 목록**: 캐릭터별 규칙 | 배운 날 | [고치기] | [지우기]

### 결과와 관리

- **설정 화면**: AI 연결 | 깨어나는 주기 | 하루 예산 | 캐릭터 파일 열기

## 정책

### 프로그램

- **한 프로그램**: 설치하면 백그라운드 서버·명령 도구·웹 화면이 함께 들어 있다.
- **로컬 주소**: 웹 화면은 내 컴퓨터 안 주소로만 열리고 밖에서 접속할 수 없다.
- **메인과 분리**: 메인 Claude Code 세션과 다른 독립 세션으로만 동작한다.
- **하나만 실행**: 같은 프로필의 서버는 한 번에 하나만 뜬다.
- **이어 하기**: 껐다 켜도 칸반·회의·대화가 멈춘 자리에서 이어진다.
- **프로필 분리**: 프로필마다 설정·기록·캐릭터가 완전히 따로 저장된다.
- **새로고침 유지**: 웹을 새로고침해도 진행 중인 회의와 컨펌 요청이 다시 뜬다.

### 명령

- **시작과 멈춤**: 명령 하나로 서버를 켜고 끄고 상태를 본다.
- **새 기획**: 명령이나 웹에서 새 기획을 만들고 할 일을 맡긴다.
- **열기**: 명령 하나로 브라우저에 사무실 화면을 연다.
- **진단**: 진단 명령은 설정·AI 연결·저장소 문제를 찾고 고칠 방법을 보인다.
- **로그**: 서버와 캐릭터 기록을 명령으로 볼 수 있다.

### 온보딩

- **AI 탐지**: 온보딩은 이 컴퓨터에서 쓸 수 있는 AI를 먼저 찾아 보인다.
- **세 자리**: 작성 AI·검토 AI·잡담 AI를 각각 고른다.
- **검증 후 저장**: 고른 AI는 실제로 한 번 불러 본 뒤에만 저장한다.
- **다른 검토**: 검토 AI는 작성 AI와 다른 회사 모델을 추천한다.

### 격리

- **설정 차단**: 팀 세션은 내 Claude Code 설정·플러그인·훅·MCP를 읽지 않는다.
- **지침 차단**: 팀 세션은 내 CLAUDE.md와 자동 메모리를 읽지 않는다.
- **우리 지침만**: 캐릭터는 자기 캐릭터 파일만 지침으로 받는다.
- **작업 폴더**: 팀 세션은 기획 워크스페이스 폴더 안에서만 파일을 다룬다.
- **설정 보존**: 프로그램은 내 Claude Code·Codex 설정 파일을 고치지 않는다.

### 로그인

- **방식 선택**: 온보딩에서 API 키 또는 로컬 CLI 재사용 중 하나를 고른다.
- **API 키 기본**: 기본값과 친구 공유는 각자 API 키를 넣는 방식이다.
- **CLI 재사용**: 로컬 CLI 재사용은 나 혼자 쓸 때 설정에서 직접 켜야 한다.
- **구독 로그인 금지**: 프로그램 안에 claude.ai 구독 로그인 창을 두지 않는다.
- **모델과 구동 분리**: 쓸 모델과 구동 방식은 따로 고른다.

### 팀

- **고정 역할**: 팀은 PM·스토리텔러·UX 설계자·화면 담당·정책 담당·검토단·서기다.
- **담당 섹션**: 기획서 섹션마다 담당 캐릭터가 하나씩 정해져 있다.
- **단일 창구**: 기획자와 대화하는 캐릭터는 PM 하나뿐이다.
- **PM 경유**: 모든 결과물은 PM을 거쳐 기획자에게 간다.
- **영속 팀원**: 팀원은 일회용이 아니라 기억을 가진 같은 캐릭터로 계속 일한다.
- **성격**: 캐릭터 성격은 말투만 바꾸고 규칙은 바꾸지 않는다.
- **서기는 코드**: 서기의 요약 외 검사·정리·빌드는 AI 없이 프로그램이 한다.

### 캐릭터 파일

- **파일 구성**: 캐릭터마다 정체성·말투·역할·기억·취향·스킬 파일을 둔다.
- **직접 수정**: 기획자는 캐릭터 파일을 열어 직접 고칠 수 있다.
- **글자 상한**: 기억은 2천 자, 취향은 1천2백 자를 넘지 않는다.
- **사용률 표시**: 캐릭터는 자기 기억이 얼마나 찼는지 보며 정리한다.
- **회의 단위 반영**: 일하는 중 바뀐 기억은 다음 회의부터 지침에 반영된다.
- **공통 취향**: 모든 캐릭터가 함께 보는 기획자 공통 취향 파일이 하나 있다.

### 캐릭터 행동

- **스스로 깨어남**: 캐릭터는 진행 중 30초, 대기 중 10분마다 스스로 깨어난다.
- **먼저 확인**: 깨어나면 프로그램이 할 일을 먼저 보고 없으면 AI를 부르지 않는다.
- **즉시 깨움**: 메시지를 받거나 카드가 배정되면 바로 깨어난다.
- **정해진 행동**: 행동은 작성·논의·코멘트·회의 요청·검토·분해·보고·쉬기뿐이다.
- **역할 제한**: 회의 요청·분해·보고는 PM만, 검토는 검토단만 한다.
- **한 번에 하나**: 캐릭터 하나는 한 번에 한 가지 일만 한다.
- **이동 연출**: 동료와 논의할 때는 그 자리로 걸어가 말풍선으로 말한다.
- **말풍선 길이**: 말풍선도 한 문장 60자 규칙을 따른다.
- **결과 반응**: 카드가 끝나면 환호하고 반려되면 시무룩해진다.
- **기록**: 모든 대화와 행동은 시간순 타임라인에 남는다.

### 칸반

- **열 구성**: 요청·요구사항 회의·팀 논의·팀 리뷰·결과 컨펌·완료 여섯 열이다.
- **카드 단위**: 카드 하나는 기획서 섹션 하나 또는 소제목 하나다.
- **배정**: 캐릭터당 카드는 한 장이고 팀 전체는 동시에 세 장까지 움직인다.
- **잠금**: 카드를 집은 캐릭터 외에는 그 카드를 고칠 수 없다.
- **잠금 해제**: 10분 동안 소식이 없는 카드는 회수해 다시 배정한다.
- **선행 순서**: 앞 단계 카드가 끝나야 다음 단계 카드가 움직인다.
- **막힘 표시**: 재회의를 기다리는 카드는 막힘 표시를 단다.
- **완료는 사람**: 카드를 완료로 옮길 수 있는 건 기획자의 승인뿐이다.

### 회의

- **요구사항 회의**: 할 일을 받으면 PM이 먼저 기획자와 요구사항 회의를 연다.
- **회의 참석**: 회의에는 PM과 안건을 낸 팀원만 들어온다.
- **질문 방식**: 안건은 선택지·추천 이유·직접 입력으로 묻는다.
- **안건 수**: 회의 한 번의 안건은 다섯 개를 넘기지 않는다.
- **회의 요약**: 서기가 개요·결정·미정·리스크로 회의를 요약한다.
- **지어내기 금지**: 회의 요약에는 기획자가 말하지 않은 결정을 넣지 않는다.
- **재회의 요청**: 팀 논의 중 빠진 요구사항이 나오면 PM이 재회의를 요청한다.
- **묶어서 요청**: 빠진 요구사항은 2분 또는 세 개가 모일 때까지 묶는다.
- **멈춤 범위**: 재회의를 기다리는 동안 관련 카드만 멈춘다.

### 팀 논의

- **보이는 논의**: 팀 논의는 사무실에서 캐릭터 대화로 보이게 진행한다.
- **결론 기록**: 논의 결론은 카드 코멘트로 남긴다.
- **PM 취합**: PM이 카드 코멘트를 모아 다음 단계를 정한다.
- **논쟁 상한**: 같은 두 캐릭터가 네 번 넘게 주고받으면 PM이 끼어든다.
- **넘길 때**: 일을 넘길 때는 바꾼 줄·근거·불확실한 것을 함께 넘긴다.

### 컨펌

- **결과물 단위**: 팀은 기획서 전체를 결과물로 가져와 컨펌을 받는다.
- **승인 전 금지**: 컨펌 전에는 어떤 변경도 확정 기획서에 쓰지 않는다.
- **영향 표시**: 결과물 보고는 바뀐 줄과 영향받는 다른 줄을 함께 보인다.
- **부분 반려**: 기획자는 섹션 단위로 골라 반려할 수 있다.
- **반려 복귀**: 반려된 섹션 카드만 사유와 함께 팀 논의로 돌아간다.
- **자동 백업**: 승인된 결과물을 쓰기 전에 이전 기획서를 백업한다.

### 하네스

- **단계 순서**: 정의 → 스토리 → 플로우 → 와이어프레임 → 정책 → 나머지 순으로 간다.
- **게이트**: 문장 검사를 통과하지 못한 초안은 팀 리뷰로 넘어가지 않는다.
- **재시도**: 같은 카드가 세 번 실패하면 재회의 안건으로 올린다.
- **행동 검증**: 캐릭터가 고른 행동이 역할과 단계에 맞는지 프로그램이 확인한다.
- **안건 우선**: 다음 단계를 막는 안건을 회의에서 먼저 묻는다.

### 검토

- **관점**: 개발·사업·UX·디자인·QA·보안 여섯 관점으로 본다.
- **다른 AI**: 검토는 작성 AI와 다른 AI로 해서 두 판단의 일치율을 낸다.
- **근거 필수**: 지적마다 근거가 된 줄의 키워드를 단다.
- **지적 형식**: 지적도 한 문장 규칙과 심각·주의 등급을 따른다.
- **완료 조건**: 심각 지적이 0건이어야 결과 컨펌으로 간다.

### 학습

- **배우는 때**: 결과 컨펌·반려와 회의 종료 때만 무엇을 배웠는지 돌아본다.
- **가장 큰 신호**: 기획자의 반려 사유와 교정을 가장 먼저 배운다.
- **승인 후 반영**: 배운 것은 기획자가 승인해야 다음 기획부터 쓴다.
- **교훈만**: 사건 기록이 아니라 일반화한 규칙과 이유 한 구절만 남긴다.
- **한 곳에만**: 사실과 취향은 기억에, 일하는 요령과 함정은 스킬에 둔다.
- **저장 금지**: 환경 탓 실패와 일회성 사정은 배운 것으로 남기지 않는다.
- **스킬 고정**: 역할당 스킬은 한 개에서 세 개로 두고 고치기만 한다.
- **상한 정리**: 기억이 상한을 넘으면 캐릭터가 스스로 합치고 줄인다.
- **오래된 것**: 30일 쓰지 않은 배운 것은 지우지 않고 보관으로 옮긴다.
- **배운 것 보기**: 기획자는 배운 것 목록에서 고치거나 지울 수 있다.

### 회의록

- **외부 회의록**: 다른 곳에서 한 회의록 파일을 사무실에 던지면 PM이 받는다.
- **추출**: 결정을 확정·미정·기각으로 나눠 원문 인용과 함께 뽑는다.
- **반영**: 확정 결정은 카드 코멘트로, 미정 결정은 회의 안건으로 만든다.

### 문서 원칙

- **원본**: 기획서 원본은 md 파일 하나이고 HTML은 거기서만 만든다.
- **같은 템플릿**: md와 HTML은 섹션 순서와 내용이 같다.
- **코드 금지**: 화면 배치·필드·API·데이터 구조는 쓰지 않는다.
- **사실만**: 근거 없는 내용은 줄 끝에 (가정)을 붙인다.
- **모르면 질문**: 모르는 것은 채우지 않고 열린 질문에 담는다.

### 문서 형식

- **제목**: 첫 줄은 제품 이름 제목이고 다음 줄은 인용 한 줄 정의다.
- **섹션 순서**: 문제부터 결정·열린 질문까지 열 개 섹션 순서를 지킨다.
- **줄 형식**: 모든 줄은 굵은 키워드, 쌍점, 한 문장 순서다.
- **스토리 형식**: 도메인 스토리는 번호와 함께 누가 무엇을 한다로 쓴다.
- **소제목**: 유저플로우·와이어프레임·정책만 소제목으로 묶는다.
- **플로우 형식**: 단계는 화살표로 잇고 분기는 물음표 뒤 예·아니오로 쓴다.
- **분기 위치**: 분기는 한 줄의 마지막 단계에만 둔다.
- **행동 표기**: 대괄호로 감싼 단계는 사람이 누르는 행동이다.
- **화면 판정**: 와이어프레임 줄이 있는 단계만 화면으로 그린다.
- **와이어 형식**: 와이어프레임 요소는 세로 막대로 나누고 단추는 대괄호다.
- **단추 이동**: 단추 안 화살표는 눌렀을 때 갈 화면을 뜻한다.
- **결정 형식**: 결정 줄 끝에는 괄호로 출처를 단다.
- **질문 형식**: 열린 질문은 키워드 앞에 물음표, 끝에 담당자를 단다.

### 린트

- **한 문장**: 한 줄에 문장 끝 부호가 두 번 나오면 오류다.
- **길이**: 키워드 뒤 문장이 60자를 넘으면 경고, 90자면 오류다.
- **코드 흔적**: 백틱·파일 경로·영문 변수명·API 경로가 보이면 오류다.
- **고유명사 허용**: 제품·회사 이름 같은 고유명사는 코드 흔적으로 보지 않는다.
- **길이 예외**: 플로우와 와이어프레임 줄은 문장이 아니라 길이 검사에서 뺀다.
- **섹션 검사**: 섹션이 빠지거나 순서가 바뀌면 오류다.
- **줄 수 상한**: 문제·목표 지표는 3줄, 리스크는 5줄을 넘으면 경고다.
- **키워드 중복**: 같은 섹션 안에서 키워드가 겹치면 오류다.
- **플로우 문법**: 화살표·분기 형식이 틀린 플로우 줄은 오류다.
- **행위자 확인**: 스토리 행위자가 사용자 역할에 없으면 오류다.
- **화면 연결**: 와이어프레임 화면이 어느 플로우에도 없으면 오류다.
- **단추 대상**: 단추가 가리키는 화면이 없으면 오류다.

### 비용

- **모델 3단**: 잡담은 가벼운 모델, 작성은 좋은 모델, 검토는 다른 회사 모델로 한다.
- **하루 예산**: 하루 사용량이 상한을 넘으면 팀이 쉬고 기획자에게 알린다.
- **사용량 표시**: 사무실 화면에 오늘 사용량을 늘 보인다.
- **주기 설정**: 캐릭터가 스스로 깨어나는 주기는 설정에서 바꾼다.

### 저장과 공유

- **워크스페이스**: 기획마다 폴더 하나에 원본 md·HTML·자료·백업을 둔다.
- **상태 분리**: 설정·대화·칸반 기록은 워크스페이스와 다른 상태 폴더에 둔다.
- **git 친화**: 워크스페이스는 그대로 git에 넣어 줄 단위 변경을 볼 수 있다.
- **로컬 전용**: 자료와 기획서는 선택한 AI 외에 밖으로 보내지 않는다.
- **HTML 한 파일**: 내보낸 HTML은 외부 의존 없이 오프라인에서 열린다.
- **클릭 이동**: HTML에서 플로우 단계를 누르면 그 와이어프레임으로 간다.
- **친구 공유**: 친구에게는 HTML 파일 하나를 보낸다.

### 화면

- **픽셀 아트**: 사무실과 캐릭터는 픽셀 아트로 그린다.
- **같은 렌더**: 웹의 문서 보기와 내보낸 HTML은 같은 화면이다.
- **한글 검색**: 타임라인은 한글 한두 글자로도 대화를 찾을 수 있다.
- **테마**: 라이트·다크 모드를 지원한다.

## 하지 않는 것

- **멀티 사용자**: 계정·권한·실시간 공동 편집은 없다.
- **메신저 연동**: 슬랙·텔레그램 같은 채널 연결은 없다.
- **기능 명세**: 요구사항·기능·상세 계층과 9슬롯은 쓰지 않는다.
- **고해상도 화면**: 와이어프레임은 상자와 글자만 그린다.
- **외부 연동**: MCP 서버·이슈 트래커·Figma·엑셀 내보내기는 없다.
- **클라우드 호스팅**: 서버에 올려 남이 접속하게 하지 않는다.

## 리스크

- **토큰 비용**: 캐릭터가 많이 대화할수록 비용이 빠르게 는다.
- **잘못 배움**: 반려 사유를 잘못 일반화하면 이후 기획이 나빠진다.
- **약관 변화**: 로컬 CLI 재사용 정책이 바뀌면 그 방식을 막아야 한다.
- **CLI 변화**: Claude Code·Codex 옵션이 바뀌면 격리가 깨질 수 있다.
- **연출 과잉**: 캐릭터 연출이 실제 진행보다 느리게 느껴질 수 있다.
