# 기획 작성법

> 요구사항을 사람이 세워 잠그고, 그 위에 인터뷰로 PRD를 채운다.
> 작업 파일은 `plan.md` 하나이고, 끝나면 문서 폴더(보통 `<프로젝트>/docs`)의 `{feature}/prd.md`로 내보낸다.
> AI는 묻고, 답을 옮기고, 하네스로 검토한다. 사람이 하지 않은 말을 덧붙이지 않는다.

---

## 1. 단계

| 단계 | 사람이 하는 일 | 끝나는 조건 |
|---|---|---|
| 요구사항 › 1. 페르소나 | 누가 쓰는지, 무엇을 원하는지, 평소 어떻게 하는지 답한다 | 페르소나마다 원하는 것과 행동 패턴이 있다 |
| 요구사항 › 2. 요구사항 | 페르소나의 필요에서 무엇을 해 줄지 정한다 | 요구사항마다 누구·왜·우선순위가 있다 |
| 요구사항 › 3. 완성 기준 | 요구사항마다 "이게 되면 완성"을 정한다 | 요구사항마다 완성 기준이 있다 |
| 요구사항 › 4. 범위와 잠금 | 이번에 안 하는 것을 말하고, 요구사항 전체를 확인한다 | `lock`으로 잠갔다 |
| PRD › 5. 요약과 목표 | 무엇을 왜 하는지, 무엇이 되면 성공인지 말한다 | 요약·배경이 있고 목표마다 확인 방법이 있다 |
| PRD › 6. 정책 | 요구사항마다 어떤 규칙으로 동작하는지 답한다 | 요구사항마다 정책이 있다 |
| PRD › 7. 확정 | 선택 구역에 답하고 PRD를 확정한다 | 상태가 `확정`이다 |

- 한 단계의 검토 결과가 0건이 돼야 다음 단계로 넘어간다.
- 잠근 뒤 요구사항(페르소나, 요구사항, 완성 기준, 범위 밖)이 바뀌면 4단계로 돌아간다. 사람이 확인하면 `unlock` 뒤 다시 `lock`한다.
- PRD가 확정되면 `prd.md`를 내보낸다. 여기서 끝내거나 SDD로 넘어간다.

---

## 2. 요구사항 단계

- 페르소나는 나이·직업보다 이 기능을 쓰는 상황과 습관으로 정한다.
- 원하는 것은 사용자의 말투로 쓴다. 예: "오타를 발견하면 바로 고치고 싶다".
- 행동 패턴이 근거 없는 추측이면 끝에 `(가정)`을 붙이고 정할 것에 확인 질문을 남긴다.
- 요구사항 제목은 "누가 무엇을 할 수 있다" 한 문장으로 쓴다.
- `왜`에는 페르소나의 원하는 것이나 불편 중 무엇을 푸는지 쓴다.
- `우선순위`는 `꼭`(없으면 내보낼 수 없다) 또는 `나중에`(이번에 못 해도 된다)다.
- 완성 기준은 사람이 눈으로 확인할 수 있는 결과로 쓴다.
- 이번에 하지 않는 기준은 지우지 않고 `[제외: 사유]`를 붙인다. 기능 단위로 빼는 것은 `범위 밖`에 쓴다.
- 요청에 없는 기능을 AI가 제안해 넣지 않는다.

---

## 3. PRD 단계

- 요약은 무엇을, 누구에게, 왜 하는지 3줄 안으로 쓴다. 이것만 읽어도 무슨 일인지 알아야 한다.
- 배경은 5줄 안으로, 지금 겪는 문제와 숫자를 쓴다.
- 목표는 바뀌어야 하는 결과를 쓰고, `확인:`에 무엇으로 아는지 쓴다. 숫자가 없으면 무엇을 보고 알지 쓴다.
- 정책은 요구사항이 어떤 규칙으로 동작하는지 7줄 안으로 쓴다. 예: "고친 횟수에는 제한이 없다".
- 예외는 정책과 다르게 처리하는 경우만 `상황 → 처리` 모양으로 쓰고, 없으면 칸을 두지 않는다. 예: "관리자가 막은 글 → 작성자도 고칠 수 없다."
- 용어는 읽는 사람이 헷갈릴 말만 `용어: 뜻` 모양으로 쓴다.
- 선택 구역(용어, 지켜야 할 조건, 일정과 리스크, 참고 문서)은 한 번씩 묻고, 없으면 `없음`이라고 쓴다.
- 화면 경로, 단추·탭 이름, 색, 위치 같은 디자인은 쓰지 않는다. 무엇을 할 수 있고 무엇이 되는지만 쓴다.
- 요구사항·완성 기준·정책·예외에 화면 표현이 있으면 하네스가 `살펴볼 것`으로 알린다. 막지는 않으니 사람이 디자인 이야기인지 정한다.

## 4. 문장 규칙

사람이 3초 안에 훑어 읽고, 비개발자가 직접 쓴 것처럼 보여야 한다. 하네스가 모든 줄에 검사한다. 용어는 뜻만 보고, 참고 문서는 링크라 보지 않는다.

| 규칙 | 예 |
|---|---|
| 한 줄에 한 문장, 80자 안 | 긴 문단은 읽지 않는다 |
| 개발 용어 금지 | API, 서버, DB, 컴포넌트, 함수, JSON, null |
| 모호한 말 금지 | 적절히, 필요 시, 가능하면, 등(등을, 등이) |
| AI 상투어 금지 | 다양한, 원활, 효율적, 극대화, 핵심적, 다음과 같, 결론적으로, 한 문장에 '~적' 셋 이상 |
| 번역투 금지 | ~에 의해, 되어지다, 가지고 있다, ~을 진행하다 |
| 꾸밈 금지 | 굵게, 긴 줄표(—), 이모지 |
| "~한다"로 끝낸다 | "~합니다", "~해요", "~죠"는 쓰지 않는다. 끝의 `(가정)`은 괜찮다 |

목록의 근거는 [설계](design.md) 5장에 있다.

## 5. 파일 모양

머리 이름과 줄 모양은 [예시](../examples/post-edit/plan.md)를 따른다. 요구사항 단계 구역이 앞, PRD 구역이 뒤다.

```md
# 게시글 수정 기획

상태: 작성중
작성자: 영원

## 페르소나

### P1 글을 자주 올리는 작성자

원하는 것
- 오타를 발견하면 바로 고치고 싶다.

행동 패턴
- 글을 올린 직후 휴대폰으로 다시 읽어 본다.

## 요구사항

### R1 작성자는 올린 글을 고칠 수 있다

누구: P1
왜: 오타를 발견하면 바로 고치고 싶다.
우선순위: 꼭

완성 기준
- R1-1 작성자는 자기 글에서 고치기를 시작할 수 있다.
- R1-2 [제외: 다음 분기에 한다] 고친 기록을 다른 사람이 볼 수 있다.

정책
- 고친 횟수에는 제한이 없다.

예외
- 관리자가 막은 글 → 작성자도 고칠 수 없다.

## 범위 밖

- 관리자가 남의 글을 고치는 일은 이번에 하지 않는다.

## 요약

작성자가 올린 글을 지우지 않고 고칠 수 있게 한다.

## 배경

다시 올리면 달린 댓글이 모두 사라진다는 문의가 한 달에 30건 들어온다.

## 목표

### G1 댓글이 사라진다는 문의를 없앤다

확인: 관련 문의가 한 달 30건에서 0건이 된다.

## 용어

- 막은 글: 신고가 쌓여 관리자가 보이지 않게 한 글

## 지켜야 할 조건

- 글을 쓴 본인만 고칠 수 있다.

## 일정과 리스크

없음

## 참고 문서

없음

## 정할 것
```

| 머리 | 단계 | 하네스가 보는 것 |
|---|---|---|
| `### P숫자 이름` | 1 | 원하는 것과 행동 패턴이 하나 이상 |
| `### R숫자 제목` | 2 | `누구:`가 있는 페르소나를 가리키고 `왜:`, `우선순위:`(꼭·나중에)가 있다 |
| `완성 기준` 아래 `- R숫자-숫자 문장` | 3 | 번호가 요구사항과 맞고 겹치지 않는다 |
| `## 범위 밖` | 4 | 한 줄 이상, 없으면 `없음` |
| `## 요약`·`## 배경`·`### G숫자 목표` | 5 | 요약 3줄, 배경 5줄 안, 목표마다 `확인:` |
| `정책`·`예외` | 6 | 요구사항마다 정책 1~7줄, 예외는 선택이고 `상황 → 처리` 모양 |
| `## 용어` | 7 | 줄마다 `용어: 뜻`, 없으면 `없음` |
| `## 지켜야 할 조건`·`## 일정과 리스크`·`## 참고 문서` | 7 | 한 줄 이상, 없으면 `없음`이고 내보낼 때 빠진다 |
| `상태:`·`작성자:`·`## 정할 것` | 7 | 작성자가 있고, 정할 것이 비었고, 사람이 `확정`이라고 했다 |

## 6. 내보내는 PRD

`{문서 폴더}/{feature}/prd.md` 하나다. 위에서 아래로 왜 → 누구 → 무엇 → 어디까지 순서로 흐른다. 칸이 둘 이상인 것은 표로, 문장 여럿은 목록으로 낸다.

| 순서 | 담는 것 | 모양 |
|---|---|---|
| 머리 | `# {기능} PRD`, `작성자: … · 작성일: …`, 번호 안내(G·P·R·R1-1) | 한 줄씩 |
| 요약 → 배경 | 쓴 그대로 한 줄씩 | 목록 |
| 목표 | ID, 목표, 확인 방법 | 표 |
| 페르소나 | `### P1 이름`, 상황, 원하는 것·행동 패턴·불편 | 사람마다 제목과 목록 |
| 용어 | 용어, 뜻 | 표 |
| 요구사항 | 한눈에 보는 표(ID·요구사항·누구 `P1 이름`·우선순위) | 표 |
| 요구사항마다 | 왜 한 줄, 완성 기준 목록(제외는 끝에 사유), 정책 목록, 예외 표(상황·처리) | `####` 제목 아래 목록과 표 |
| 범위 밖 → 선택 구역 | 선택 구역이 `없음`이면 뺀다 | 목록 |

상태 줄, 정할 것, `누구:`·`우선순위:` 줄(표로 올라감)은 넣지 않는다. 작성일은 내보낸 날짜다.
