# 기획 작성법

> 기획은 요구사항을 말로 어떻게 풀지 정하는 문서이며, 비개발자가 읽어도 바로 이해되게 쓴다.
> 가장 중요한 일은 요구사항을 세우는 것이고, 요구사항은 페르소나의 필요와 행동에서 나와야 한다.
> AI는 자동으로 쓰지 않는다. 묻고, 답을 옮기고, 하네스로 검토하고, 빈 곳을 다시 묻는다.

---

## 1. 단계

| 단계 | 사람이 하는 일 | AI가 하는 일 | 끝나는 조건 |
|---|---|---|---|
| 1. 배경 | 왜 이 기능이 필요한지 말한다 | 문제와 근거를 묻고 문장으로 옮긴다 | 배경이 한 문장 이상이다 |
| 2. 페르소나 | 누가 쓰는지, 무엇을 원하는지, 평소 어떻게 행동하는지 답한다 | 사용자 유형마다 원하는 것과 행동 패턴을 묻는다 | 페르소나마다 원하는 것과 행동 패턴이 하나 이상이다 |
| 3. 요구사항 | 페르소나의 필요에서 무엇을 해 줄지 정한다 | "이 사람이 이걸 원하니 무엇을 해 줘야 하나요?"처럼 필요에서 출발해 묻는다 | 요구사항마다 누구와 왜가 있다 |
| 4. 완성 기준 | 요구사항마다 "이게 되면 완성"을 정한다 | 기준 후보를 묻고 번호를 붙인다 | 요구사항마다 완성 기준이 하나 이상이다 |
| 5. 확정 | 기획 전체를 읽고 확정한다 | 정할 것이 남았는지 확인한다 | 상태를 `확정`으로 바꾼다 |

한 단계에서 하네스 검토 결과가 0건이 돼야 다음 단계로 넘어간다.
질문은 한 번에 1~3개만 하고, 답이 없는 칸을 추측해서 채우지 않는다.

---

## 2. 페르소나를 세우는 법

- 페르소나는 나이·직업 같은 겉모습보다 이 기능을 쓰는 상황과 습관으로 정한다.
- 원하는 것은 사용자의 말투로 쓴다. 예: "오타를 발견하면 바로 고치고 싶다".
- 행동 패턴은 실제로 하는 행동을 쓴다. 예: "글을 올린 직후 휴대폰으로 다시 읽어 본다".
- 불편은 지금 겪는 문제를 쓰며, 없으면 생략한다.
- 행동 패턴이 근거 없는 추측이면 문장 끝에 `(가정)`을 붙이고 정할 것에 확인 질문을 남긴다.
- 어느 요구사항에도 쓰이지 않는 페르소나는 범위 밖이거나 요구사항이 빠진 것이므로 묻는다.

---

## 3. 요구사항을 세우는 법

- 요구사항 제목은 "누가 무엇을 할 수 있다" 한 문장으로 쓴다.
- `누구`에는 페르소나 번호를 쓴다.
- `왜`에는 그 페르소나의 원하는 것이나 불편 중 무엇을 풀어 주는지 쓴다.
- 요청에 없는 기능을 AI가 제안해 넣지 않는다.
- 완성 기준은 사람이 눈으로 확인할 수 있는 결과로 쓴다.
- 이번에 하지 않기로 한 기준은 지우지 않고 `[제외: 사유]`를 붙여 남긴다.

---

## 4. 문장 규칙

| 규칙 | 이유 |
|---|---|
| 한 줄에 한 문장만 쓴다 | 사람은 긴 문단을 읽지 않는다 |
| 개발 용어를 쓰지 않는다 (API, 서버, DB, 컴포넌트, 함수, 엔드포인트, JSON, null) | 비개발자가 읽는 문서다 |
| 모호한 말을 쓰지 않는다 (적절히, 필요 시, 가능하면, 등) | 완성인지 아닌지 판정할 수 없다 |
| 문장은 80자 안으로 쓴다 | 한눈에 읽혀야 한다 |

---

## 5. 파일 모양

파일은 `plan.md` 하나이며, 하네스가 아래 머리 이름과 줄 모양으로 읽는다.

```md
# 게시글 수정 기획

상태: 작성중

## 배경

올린 글에서 오타를 발견해도 지우고 다시 올려야 한다.
다시 올리면 달린 댓글이 모두 사라진다는 문의가 한 달에 30건 들어온다.

## 페르소나

### P1 글을 자주 올리는 작성자

동네 소식을 하루에 두세 번 올리는 사람이다.

원하는 것
- 오타를 발견하면 바로 고치고 싶다.
- 고쳐도 댓글은 그대로 남았으면 좋겠다.

행동 패턴
- 글을 올린 직후 휴대폰으로 다시 읽어 본다.

불편
- 고치려면 지우고 다시 올려야 한다.

## 요구사항

### R1 작성자는 올린 글을 고칠 수 있다

누구: P1
왜: 오타를 발견하면 바로 고치고 싶다.

완성 기준
- R1-1 작성자는 자기 글에서 고치기를 시작할 수 있다.
- R1-2 고친 뒤에도 댓글이 그대로 남는다.
- R1-3 [제외: 다음 분기에 한다] 고친 기록을 다른 사람이 볼 수 있다.

## 정할 것

- 관리자도 남의 글을 고칠 수 있는가?
```

| 머리 | 필수 | 하네스가 보는 것 |
|---|---|---|
| `상태:` | 예 | `작성중` 또는 `확정`, 확정은 사람이 말했을 때만 바꾼다 |
| `## 배경` | 예 | 한 문장 이상 |
| `### P숫자 이름` | 예 | 원하는 것과 행동 패턴이 하나 이상 |
| `### R숫자 제목` | 예 | `누구:`가 있는 페르소나를 가리키고 `왜:`와 완성 기준이 있다 |
| `- R숫자-숫자 문장` | 예 | 번호가 요구사항과 맞고 겹치지 않는다 |
| `## 정할 것` | 아니오 | 남은 항목이 있으면 확정할 수 없다 |
