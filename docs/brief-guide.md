# 비즈니스 요구사항 작성법

> 기획 1단계다. 사업 담당자를 인터뷰해 왜 지금 이 기능이 필요하고, 무엇이 되면 성공인지 정한다.
> 사람이 한 말은 원문 그대로 남기고, 기획 말로 바꾸는 일은 2단계([기획 작성법](planning-guide.md))에서 한다.
> AI는 자동으로 쓰지 않는다. 묻고, 원문을 옮기고, 하네스로 검토하고, 빈 곳을 다시 묻는다.

---

## 1. 단계

| 단계 | 사람이 하는 일 | AI가 하는 일 | 끝나는 조건 |
|---|---|---|---|
| 1-1. 기능 이름 | 기능을 한 줄로 부르고 영어 이름을 정한다 | 결과 폴더 이름이 될 영어 이름을 묻는다 | `기능:` 줄에 영어 이름이 있다 |
| 1-2. 왜 지금 | 지금 겪는 문제와 그 근거를 말한다 | 문제, 숫자, 출처를 묻는다 | 문제 문장과 근거가 하나 이상이다 |
| 1-3. 목표 | 무엇이 되면 성공인지 숫자로 말한다 | "몇이 되면 성공인가요?"처럼 지표를 묻는다 | 목표마다 지표가 있다 |
| 1-4. 비즈니스 요구사항 | 사업 입장에서 꼭 돼야 하는 것을 말한다 | 목표마다 "그러려면 무엇이 돼야 하나요?"를 묻는다 | 요구사항마다 근거 목표와 원문이 있다 |
| 1-5. 범위와 제약 | 이번에 하지 않을 것과 지켜야 할 것을 말한다 | 기한, 정책, 법, 예산을 묻는다 | 범위 밖이 한 줄 이상이다 |
| 1-6. 확정 | 전체를 읽고 확정한다 | 정할 것이 남았는지 확인한다 | 상태를 `확정`으로 바꾼다 |

---

## 2. 인터뷰하는 법

- 앞선 문서가 없으므로, 질문할 때는 사람이 방금 한 말을 원문으로 인용해 되묻는다.
- 원문은 사람 말투 그대로 `원문:` 줄에 옮기고, 다듬은 문장은 제목에만 쓴다.
- 숫자가 없는 목표는 "이게 안 되면 무엇을 잃나요?", "지금은 몇인가요?"로 숫자를 끌어낸다.
- 숫자를 끝내 모르면 `(가정)`을 붙이고 정할 것에 확인 질문을 남긴다.
- 요청에 없는 목표나 요구사항을 AI가 제안해 넣지 않는다.
- 해결 방법(화면, 단추, 기술)이 나오면 적지 않고 "그걸로 무엇을 얻고 싶으신가요?"로 되묻는다.

질문 예:

```text
근거  1-2 왜 지금 › 사람의 말
원문  "다시 올리면 댓글이 다 날아간다고 문의가 많아요"
질문  문의가 한 달에 몇 건쯤 들어오나요? 어디서 확인할 수 있나요?
```

## 3. 파일 모양

작업 파일은 `brief.md`이며, 결과물에서는 PRD 앞부분이 된다.

```md
# 게시글 수정 비즈니스 요구사항

상태: 작성중
기능: post-edit

## 왜 지금

올린 글을 고치려면 지우고 다시 올려야 한다.
근거: 다시 올리면 댓글이 사라진다는 문의가 한 달에 30건 들어온다 (고객센터 9월 집계).

## 목표

### G1 글 수정 문의를 줄인다

지표: 글 수정 관련 문의가 월 30건에서 5건 아래로 준다.

## 비즈니스 요구사항

### BR1 작성자는 다시 올리지 않고 글을 고칠 수 있어야 한다

근거 목표: G1
원문: "그냥 고치기 버튼 하나 있으면 문의가 확 줄 거예요."

## 범위 밖

- 고친 기록을 남이 보는 기능은 이번에 하지 않는다.

## 제약

- 11월 말 업데이트에 함께 나가야 한다.

## 정할 것

- 관리자 수정도 이번 범위인가?
```

| 머리 | 필수 | 하네스가 보는 것 |
|---|---|---|
| `상태:` | 예 | `작성중` 또는 `확정` |
| `기능:` | 예 | 영어 소문자, 숫자, `-`만 쓴다 |
| `## 왜 지금` | 예 | 문장과 `근거:` 줄이 하나 이상이다 |
| `### G숫자 제목` | 예 | `지표:` 줄이 있다 |
| `### BR숫자 제목` | 예 | `근거 목표:`가 있는 G를 가리키고 `원문:`이 있다 |
| `## 범위 밖` | 예 | 한 줄 이상이다 |
| `## 제약` | 아니오 | 있으면 줄마다 한 문장이다 |
| `## 정할 것` | 아니오 | 남은 항목이 있으면 확정할 수 없다 |

## 4. 검사 규칙

| 규칙 | 걸리는 경우 |
|---|---|
| 지표 없는 목표 | `G`에 `지표:`가 없거나 숫자가 없다 |
| 근거 없는 요구사항 | `BR`의 `근거 목표:`가 없는 G를 가리킨다 |
| 이어지지 않은 목표 | 어느 `BR`도 그 `G`를 근거로 쓰지 않는다 |
| 원문 없음 | `BR`에 `원문:`이 없다 |
| 해결책 섞임 | 제목에 화면·단추·기술 이름이 들어 있다 |
| 개발 용어 | [기획 작성법](planning-guide.md) 4장의 개발 용어가 쓰였다 |

문장 규칙(한 줄 한 문장, 모호한 말, 80자)은 기획 작성법 4장을 그대로 따른다. `원문:` 줄은 사람 말이라 문장 규칙에서 뺀다.
