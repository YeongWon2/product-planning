# 설계서

> 작성일 2026-10-19 · v2.0
> 사람이 요구사항을 세워 잠그고, 인터뷰로 PRD를 쓰고, 원하면 SDD까지 이어 쓰는 파이프라인이다.
> 결과물은 지금 체크아웃한 프로젝트 문서 폴더(기본 `docs`)의 `{feature}/prd.md`, `sdd.md` 두 문서다.

---

## 0. 한 장 요약

```text
요구사항 수립 ──lock──▶ PRD 인터뷰 ──확정──▶ prd.md ──┬─ 끝
 (사람이 세우고 잠금)     (잠긴 요구사항 위에)          └─▶ SDD 작성 ──확정──▶ sdd.md
```

| 항목 | 내용 |
|---|---|
| 만드는 것 | `{feature}/prd.md`(비개발자용, 표 중심), `{feature}/sdd.md`(개발자용) |
| 쓰는 사람 | 사람이 정하고, AI는 묻고 옮기고, 하네스는 검토한다 |
| 가장 중요한 것 | 요구사항은 사람이 세우고, 잠근 뒤에는 AI가 바꾸지 못한다 |
| 문서 품질 기준 | 사람이 3초 안에 훑어 흐름을 안다. 비개발자가 직접 쓴 것처럼 읽힌다 |
| 범위 밖 | 화면 디자인, 기술 컨벤션, 코드 구현 |

---

## 1. 원칙

1. **요구사항은 사람에게서 나온다.** AI는 다듬고 묻기만 하고, 요구사항을 더하거나 빼지 않는다.
2. **잠금은 검사로 지킨다.** 프롬프트로 막지 않고 하네스가 지문을 비교한다.
3. **AI는 자동으로 쓰지 않는다.** 사람이 답한 내용만 옮긴다.
4. **단계를 건너뛰지 않는다.** 한 단계의 검토 결과가 0건이어야 다음 단계로 간다.
5. **한 사실은 한 곳에만 쓴다.** PRD와 SDD에 같은 문장을 되풀이하지 않는다.
6. **완성은 셀 수 있어야 한다.** 완성 기준마다 SDD 트리의 근거 줄이 있어야 완성이다.
7. **확정은 사람만 한다.** `lock`과 `상태: 확정`은 사람이 말했을 때만 한다.
8. **3초 안에 훑게 쓴다.** 결론을 위에, 한눈에 보는 표를 앞에, 구역은 짧게.

## 2. 세 단계

| | 1. 요구사항 수립 | 2. PRD 인터뷰 | 3. SDD 작성 |
|---|---|---|---|
| 묻는 것 | 누가, 무엇을, 왜, 무엇이 되면 완성, 무엇을 안 하나 | 요약, 배경, 목표, 요구사항별 정책·예외, 조건·일정 | 상태, 권한 조건, 상태·조건별 유저 플로우 |
| 작업 파일 | `plan.md` 앞쪽 | `plan.md` 뒤쪽 | `sdd.md`, `trace.json` |
| 끝나는 때 | 사람이 확인하고 `lock` | 사람이 `상태: 확정` | 모든 완성 기준이 트리와 대조되고 `상태: 확정` |
| 남는 것 | (PRD 안에 들어간다) | `docs/{feature}/prd.md` | `docs/{feature}/sdd.md` |
| 읽는 사람 | 기획자 | 비개발자, 팀 전체 | 개발자 |
| 작성법 | [기획 작성법](planning-guide.md) 2장 | [기획 작성법](planning-guide.md) 3장 | [SDD 스펙 작성법](sdd-guide.md) |

- 요구사항을 따로 내보내지 않는 까닭: 요구사항은 PRD를 쓰기 위한 재료다. 한 문서에 두어야 읽는 사람이 한 곳만 본다.
- PRD에서 끝내도 된다. 작업 폴더를 남겨 두면 나중에 SDD를 이어 쓴다.

## 3. 흐름과 되돌아가기

```text
         ┌──────────── 매 답마다: 옮기기 → check → "추가되어야 완성" → 질문 ────────────┐
         ▼                                                                         │
요구사항 1~4 ──lock──▶ PRD 5~7 ──확정──▶ export(prd.md) ──▶ SDD 8~13 ──확정──▶ export(sdd.md)
    ▲                    │                                    │
    └──── unlock ────────┴──── 요구사항을 바꿔야 할 때 ──────────┘
```

| 일이 생기면 | 하는 일 |
|---|---|
| PRD나 SDD를 쓰다 요구사항을 바꿔야 한다 | `unlock` → 고침 → 사람 확인 → `lock`. 바뀐 완성 기준은 SDD 대조가 낡은 것으로 다시 잡는다 |
| PRD 정책만 바꾼다 | 잠금은 그대로다. `상태: 작성중`으로 돌리고 다시 확정한다 |
| 이미 낸 `prd.md`와 내용이 달라졌다 | `export`가 멈춘다. 사람이 확인하면 `--force`로 덮어쓴다 |

## 4. 하네스와 모델의 역할

| 일 | 하네스 | 모델 | 사람 |
|---|---|---|---|
| 문서 내용 정하기 | | | 한다 |
| 질문 만들기 | 걸린 것을 알려 준다 | 사람 말로 바꿔 입력창으로 묻는다 | |
| 답을 문서로 옮기기 | | 짧게 옮긴다 | 확인한다 |
| 형식·문장·AI 말투 검사 | 한다 | | |
| 요구사항 잠금 | 지문을 남기고 비교한다 | | 잠그라고 한다 |
| 요구사항 대조 | 근거 줄이 실제로 있는지 센다 | 기준마다 근거 줄을 찾는다 | 빠졌다고 나온 것에 답한다 |
| 내보내기 | 확정된 문서만 `{문서 폴더}/{feature}/`에 쓴다 | | 어디서 끝낼지, 어느 문서 폴더에 둘지 정한다 |

단계 번호와 판정 조건은 [하네스](harness.md) 5장에 있다.

## 5. 문서 작성 규칙의 근거

사람이 쓴 것처럼, 3초 안에 훑게 쓰는 규칙은 아래 레퍼런스에서 가져왔다. 스타 수는 2026-10-19 기준이다.

| 레퍼런스 | 스타 | 가져온 것 |
|---|---|---|
| [blader/humanizer](https://github.com/blader/humanizer) | 58k | AI 상투어, 굵게·긴 줄표 같은 꾸밈, 예고·결산 문장 금지 |
| [hardikpandya/stop-slop](https://github.com/hardikpandya/stop-slop) | 18k | 막연한 선언 대신 구체적인 내용, 서두 군더더기 금지 |
| [IsaacEryn/humanizer-ko](https://github.com/IsaacEryn/humanizer-ko) | 5 | 한국어 AI 어휘, 한 문장 '~적' 밀도, 번역투(~에 의해, 가지고 있다) |
| [dotoricode/korean-humanizer](https://github.com/dotoricode/korean-humanizer) | 15 | 한국어 상투어 목록. 문맥을 보고 고친다는 원칙 |
| [nathankim0/humanize-korean](https://github.com/nathankim0/humanize-korean) | 2 | '~를 통해'처럼 실제 뜻이 있을 수 있는 표현은 막지 않는다 |
| [RichardLitt/standard-readme](https://github.com/RichardLitt/standard-readme) | 6k | README 순서: 한 줄 설명 → 설치 → 사용법 |
| [matiassingers/awesome-readme](https://github.com/matiassingers/awesome-readme) | 21k | 흐름 그림과 표로 먼저 보여 주는 README 사례 |
| [Diátaxis](https://github.com/evildmp/diataxis-documentation-framework) | 1k | 한 문서에 한 가지 목적. 설계·작성법·하네스 문서를 나눈 기준 |

- 기계 검사로 넣은 것: 상투어, 번역투, 꾸밈, 존댓말, 길이. 오탐이 적은 것만 골랐다(`src/text.mjs`).
- 사람이 보는 것: 결론이 맨 위에 있는가, 머리만 읽어도 흐름이 보이는가, 셋씩 나열하는 습관, 끝에 붙는 경구.
- 한국어 레퍼런스는 스타가 적다. 그래서 목록을 짧게 두고, 막을 때도 고칠 방향을 함께 알려 준다.

## 6. 구성

| 위치 | 내용 |
|---|---|
| `scripts/pp.mjs` | 하네스 CLI (`init`, `check`, `lock`, `unlock`, `sheet`, `export`, `discard`) |
| `src/plan.mjs` | 요구사항·PRD 읽기와 1~7단계 검사, 잠금 지문 |
| `src/sdd.mjs`, `src/trace.mjs` | SDD 읽기와 8~13단계 검사, 요구사항 대조 |
| `src/text.mjs` | 문장 규칙과 AI 말투 검사 |
| `src/export.mjs` | `docs/{feature}/` 내보내기 |
| `skills/yw-plan/` | 요구사항 수립과 PRD 인터뷰를 이끄는 스킬 |
| `skills/yw-sdd/` | SDD 작성을 이끄는 스킬 |
| `examples/post-edit/` | 끝까지 통과한 예시 |
