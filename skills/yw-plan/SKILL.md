# 요구사항 세우고 PRD 쓰기

요청: $ARGUMENTS

요청이 비어 있으면 "무엇을 기획할까요? 누가 무엇을 하고 싶은지 한 줄로 알려 주세요."라고만 묻고 기다린다.

- 작성법: 이 스킬 폴더 기준 `../../docs/planning-guide.md` — 시작할 때 한 번 읽는다
- 하네스: `node <플러그인 루트>/scripts/pp.mjs` (플러그인 루트 = 이 스킬 폴더의 두 단계 위)
- 하네스 보고 모양과 단계 순서: `../../docs/harness.md` 4·5장

## 1. 지켜야 할 것

- 문서 내용은 사람이 정한다. AI는 묻고, 받은 답을 옮기고, 검토 결과를 보여 준다.
- 사람이 말하지 않은 페르소나·요구사항·완성 기준·정책을 추측해 넣지 않는다.
- 요청에 없는 기능을 제안해 넣지 않는다.
- 사람이 한 말을 짧게 옮긴다. 하지 않은 말을 덧붙이거나 꾸미지 않는다. 비개발자가 직접 쓴 것처럼 보여야 한다.
- 요구사항은 잠근 뒤 사람이 바꾸자고 할 때만 고친다.
- `lock`과 `상태: 확정`은 사람이 확인했다고 말했을 때만 한다.
- 기획 내용을 메모리에 남기지 않는다. 프로젝트에 남는 것은 내보낸 `{feature}/` 폴더의 문서뿐이다.

## 2. 시작

1. 작업 폴더는 프로젝트 밖 `~/.product-planning/work/{영어 기능 이름}/`에 둔다.
2. `pp.mjs init <폴더> <기능 이름>`으로 `plan.md` 틀을 만든다. 이미 있으면 그대로 이어서 쓴다.
3. `pp.mjs check <폴더>`를 돌려 지금 단계를 확인하고 그 단계의 첫 질문을 한다.

## 3. 매 답의 루프

1. 사람이 답한다.
2. 답을 `plan.md`의 해당 칸에 옮긴다.
3. `pp.mjs check <폴더>`를 돌린다.
4. 보고의 "추가되어야 완성" 가운데 사람 답이 필요한 것을 질문 1~3개로 바꿔 `AskUserQuestion` 입력창으로 묻는다.
5. 번호 순서, 머리 이름, AI 말투처럼 형식만 틀린 것은 묻지 않고 고친 뒤 3으로 돌아간다. 뜻이 바뀌면 묻는다.
6. 걸린 것이 없어 단계가 바뀌면, 바뀐 단계를 한 줄로 알리고 그 단계 첫 질문을 한다.

매 바퀴 보여 주는 것은 하네스 보고의 `단계`·`추가되어야 완성`·`살펴볼 것` 줄과 질문뿐이다. 이미 한 일이나 규칙 설명은 되풀이하지 않는다.

## 4. 단계마다 묻는 법

| 단계 | 묻는 것 | 예 |
|---|---|---|
| 페르소나 | 누가 쓰는지, 무엇을 원하는지, 평소 어떻게 하는지 | "이 사람은 보통 언제, 어디서 이걸 하나요?" |
| 요구사항 | 페르소나의 필요에서 무엇을 해 줘야 하는지, 꼭 할지 나중에 할지 | "P1이 '바로 고치고 싶다'고 했는데, 무엇을 할 수 있어야 하나요?" |
| 완성 기준 | 요구사항마다 무엇이 되면 완성인지 | "R1은 어떤 모습을 보면 다 됐다고 할 수 있나요?" |
| 범위와 잠금 | 이번에 안 하는 것, 그리고 요구사항 전체를 보여 주고 잠가도 되는지 | "이대로 요구사항을 잠글까요?" |
| 요약과 목표 | 무엇을 왜 하는지, 무엇이 되면 성공인지, 그걸 무엇으로 아는지 | "이 기능이 나가면 무엇이 달라져야 하나요?" |
| 정책 | 요구사항마다 규칙, 예외(상황 → 처리) | "R1은 몇 번까지 고칠 수 있나요? 못 고치는 경우가 있나요?" |
| 확정 | 용어, 선택 구역, 작성자, 정할 것, PRD 전체 확인 | "읽는 사람이 헷갈릴 말이 있나요?" |

- 페르소나는 겉모습보다 사용 상황과 습관을 묻는다.
- 사람이 요구사항을 잠그라고 하면 `pp.mjs lock <폴더>`를 돌리고, 잠근 요구사항·완성 기준 수를 한 줄로 알린다.
- 정책은 요구사항 하나씩, 잠긴 완성 기준을 보여 주며 묻는다.
- 화면 경로·단추 이름·색·위치 같은 디자인 이야기는 옮기지 않는다. 무엇이 되는지만 옮긴다.
- 보고에 `살펴볼 것`의 `[디자인 표현]`이 나오면 무엇이 되는지로 바꿔 쓸지 입력창으로 묻는다. 잠근 요구사항이면 바꾸기 전에 `unlock`한다. 업무 말(예: 팝업 스토어)이면 그대로 둔다.
- 답이 다른 단계의 것이면 지금 단계에 필요한 부분만 옮기고 "나중 단계에서 다룰게요"라고 알린다.

## 4.1 질문은 입력창으로 한다

모든 질문은 텍스트로 쓰지 않고 `AskUserQuestion` 도구로 한다.

- 한 번에 질문 1~3개, 질문마다 선택지 2~4개를 준다. 사람은 고르거나 "Other"에 직접 쓴다.
- `header`는 지금 단계나 걸린 종류로 짧게 쓴다. 예: `페르소나`, `R1 정책`
- 추천이 있으면 첫 선택지로 두고 이름 끝에 `(추천)`, 설명에 이유 한 줄을 쓴다.
- 답 후보는 사람이 이미 한 말과 기획에 있는 내용에서만 만든다. 새 사실을 지어낸 후보는 주지 않는다.
- 여러 개를 같이 고를 수 있는 질문은 `multiSelect`를 켠다.
- 사람이 Other에 되묻는 말을 쓰면, 먼저 텍스트로 답하고 같은 질문을 다시 입력창으로 띄운다.

## 5. 대화 중에 바뀌는 것

- 잠근 뒤 요구사항을 바꾸자고 하면 `pp.mjs unlock <폴더>`로 풀고 고친 뒤, 사람이 확인하면 다시 `lock`한다.
- 확정한 PRD를 바꾸면 `상태: 작성중`으로 돌리고 다시 확정받는다.
- 사람이 "이건 이번에 안 한다"고 하면 완성 기준에 `[제외: 사유]`를 붙여 남긴다. 잠근 뒤라면 이것도 요구사항을 바꾸는 일이므로 `unlock`부터 한다.

## 6. 끝

하네스 보고가 PRD 확정을 알리면(다음 줄이 export를 안내한다):

1. `pp.mjs export <폴더> <문서 폴더>`로 `{문서 폴더}/{feature}/prd.md`를 쓴다. 문서 폴더는 지금 체크아웃한 저장소의 `docs`가 기본이다. 저장소가 `docs` 아래를 주제별로 나눠 쓰면 그 폴더를 입력창으로 묻는다.
2. 파일이 이미 있고 내용이 다르면 덮어쓸지 입력창으로 묻고, 원하면 `--force`를 붙인다.
3. 쓴 경로와 요구사항·완성 기준 수를 한 줄로 알린다.
4. "여기서 끝낼까요, SDD로 넘어갈까요?"를 입력창으로 묻는다.
   - SDD로 가면 `/yw-sdd <폴더>`의 절차로 이어 간다.
   - 끝내면 `pp.mjs discard <폴더>`로 작업 폴더를 지울지 묻는다. 남겨 두면 나중에 SDD를 이어 쓸 수 있다.
