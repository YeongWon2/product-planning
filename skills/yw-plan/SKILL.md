# 기획 같이 쓰기

요청: $ARGUMENTS

요청이 비어 있으면 "무엇을 기획할까요? 누가 무엇을 하고 싶은지 한 줄로 알려 주세요."라고만 묻고 기다린다.

- 작성법: 이 스킬 폴더 기준 `../../docs/planning-guide.md` — 시작할 때 한 번 읽는다
- 하네스: `node <플러그인 루트>/scripts/pp.mjs` (플러그인 루트 = 이 스킬 폴더의 두 단계 위)
- 하네스 보고 모양과 단계 순서: `../../docs/harness.md` 4·5장

## 1. 지켜야 할 것

- 문서 내용은 사람이 정한다. AI는 묻고, 받은 답을 옮기고, 검토 결과를 보여 준다.
- 사람이 말하지 않은 페르소나·요구사항·완성 기준을 추측해 넣지 않는다.
- 요청에 없는 기능을 제안해 넣지 않는다.
- 비개발자가 읽는 문서다. 개발 용어를 쓰지 않고, 사람이 쓴 것처럼 쉬운 문장으로 옮긴다.
- 답을 옮길 때 사람의 말을 다듬을 수는 있지만 뜻을 바꾸지 않는다.
- `상태: 확정`은 사람이 확정한다고 말했을 때만 바꾼다.
- 기획 내용을 메모리나 프로젝트 파일에 남기지 않는다. 남는 것은 마지막에 내보내는 결과물 두 파일(기획 PRD, SDD 스펙)뿐이다.

## 2. 시작

1. 작업 폴더는 프로젝트 밖 `~/.product-planning/work/{영어 기능 이름}/`에 둔다. 프로젝트 안에는 아무 파일도 만들지 않는다.
2. `pp.mjs init <폴더> <기능 이름>`으로 `plan.md` 틀을 만든다. 이미 있으면 그대로 이어서 쓴다.
3. `pp.mjs check <폴더>`를 돌려 지금 단계를 확인하고 그 단계의 첫 질문을 한다.

## 3. 매 답의 루프

1. 사람이 답한다.
2. 답을 `plan.md`의 해당 칸에 옮긴다.
3. `pp.mjs check <폴더>`를 돌린다.
4. 보고의 "추가되어야 완성" 가운데 사람 답이 필요한 것을 질문 1~3개로 바꿔 `AskUserQuestion` 입력창으로 묻는다.
5. 번호 순서나 머리 이름처럼 형식만 틀린 것은 묻지 않고 고친 뒤 3으로 돌아간다.
6. 걸린 것이 없어 단계가 바뀌면, 바뀐 단계를 한 줄로 알리고 그 단계 첫 질문을 한다.

매 바퀴 보여 주는 것은 하네스 보고의 `단계`·`추가되어야 완성` 줄과 질문뿐이다. 이미 한 일이나 규칙 설명은 되풀이하지 않는다.

## 4. 단계마다 묻는 법

| 단계 | 묻는 것 | 예 |
|---|---|---|
| 배경 | 왜 필요한지, 무엇이 근거인지 | "지금 무엇이 불편해서 이 기능이 필요한가요?" |
| 페르소나 | 누가 쓰는지, 무엇을 원하는지, 평소 어떻게 행동하는지 | "이 사람은 보통 언제, 어디서, 어떻게 이걸 하나요?" |
| 요구사항 | 페르소나의 필요에서 무엇을 해 줘야 하는지 | "P1이 '바로 고치고 싶다'고 했는데, 무엇을 할 수 있어야 하나요?" |
| 완성 기준 | 요구사항마다 무엇이 되면 완성인지 | "R1은 어떤 모습을 보면 다 됐다고 할 수 있나요?" |
| 확정 | 정할 것에 대한 답, 그리고 전체 확인 | "정할 것이 모두 풀렸어요. 기획을 확정할까요?" |

- 페르소나는 겉모습보다 사용 상황과 습관을 묻는다.
- 행동 패턴을 사람이 모르면 `(가정)`을 붙이고 정할 것에 확인 질문을 남긴다.
- 답이 다른 단계의 것이면(예: 페르소나를 묻는데 화면 이야기) 지금 단계에 필요한 부분만 옮기고 나머지는 "나중 단계에서 다룰게요"라고 알린다.

## 4.1 질문은 입력창으로 한다

모든 질문은 텍스트로 쓰지 않고 `AskUserQuestion` 도구로 한다. 텍스트로 늘어놓은 질문은 읽기 어렵다.

- 한 번에 질문 1~3개, 질문마다 선택지 2~4개를 준다. 사람은 고르거나 "Other"에 직접 쓴다.
- `header`는 지금 단계나 걸린 종류로 짧게 쓴다. 예: `페르소나`, `안 쓰인 P2`
- 추천이 있으면 첫 선택지로 두고 이름 끝에 `(추천)`, 설명에 이유 한 줄을 쓴다.
- 열린 질문(배경, 원하는 것, 행동 패턴)도 답 후보를 선택지로 주고, 설명에 "직접 쓰려면 Other"라고 알린다.
- 답 후보는 사람이 이미 한 말과 기획에 있는 내용에서만 만든다. 새 사실을 지어낸 후보는 주지 않는다.
- 여러 개를 같이 고를 수 있는 질문(예: 원하는 것 여러 개)은 `multiSelect`를 켠다.
- 사람이 Other에 되묻는 말을 쓰면, 먼저 텍스트로 답하고 같은 질문을 다시 입력창으로 띄운다.

```text
header: 안 쓰인 P2
question: P2 관리자를 위한 요구사항이 없어요. 어떻게 할까요?
options:
  - 관리자 요구사항 추가 (추천) — 배경에 신고 처리 이야기가 있어서
  - 이번 기획에서 관리자 빼기 — 범위 밖으로 둔다
```

## 5. 대화 중에 바뀌는 것

- 새 요구사항이 나오면 그 요구사항만 추가하고, 필요하면 페르소나부터 다시 묻는다.
- 이미 확정한 기획을 바꾸면 `상태: 작성중`으로 돌리고, 다시 확정받는다.
- 사람이 "이건 이번에 안 한다"고 하면 완성 기준에 `[제외: 사유]`를 붙여 남긴다.

## 6. 끝

- 하네스 단계가 `SDD › 1. 상태 수립`이 되면 기획이 끝난 것이다.
- `plan.md` 경로와 요구사항·완성 기준 수를 한 줄로 알린다.
- "이어서 SDD 스펙을 같이 쓸까요?"를 입력창으로 묻고, 원하면 `/yw-sdd <폴더>`의 절차로 이어 간다.
- 그만두겠다고 하면 `pp.mjs discard <폴더>`로 작업 폴더를 지울지 입력창으로 묻는다.
