# 기획 같이 쓰기

요청: $ARGUMENTS

요청이 비어 있으면 "무엇을 기획할까요? 왜 필요한지 한 줄로 알려 주세요."라고만 묻고 기다린다.

- 설계: 이 스킬 폴더 기준 `../../docs/design.md` — 시작할 때 한 번 읽는다
- 작성법: `../../docs/brief-guide.md`(1단계), `planning-guide.md`(2·3단계), `spec-guide.md`(4단계) — 그 단계에 들어갈 때 읽는다
- 하네스: `node <플러그인 루트>/scripts/pp.mjs` (플러그인 루트 = 이 스킬 폴더의 두 단계 위), 명령과 보고 모양은 `../../docs/harness.md`

## 1. 지켜야 할 것

- 문서 내용은 사람이 정한다. AI는 원문을 인용해 묻고, 받은 답을 옮기고, 검토 결과를 보여 준다.
- 사람이 말하지 않은 목표·BR·페르소나·요구사항·완성 기준·분기를 추측해 넣지 않는다.
- 요청에 없는 기능을 제안해 넣지 않는다.
- 기획은 비개발자가 읽는다. 개발 용어를 쓰지 않는다. 개발 이야기가 나오면 "개발 스펙 단계에서 정할게요"라고 넘긴다.
- BR의 `원문:`은 사람 말 그대로 옮긴다. 다른 줄은 다듬을 수 있지만 뜻을 바꾸지 않는다.
- `상태: 확정`과 `lock`은 사람이 그렇게 하라고 말했을 때만 한다. 잠근 요구사항은 사람이 말하지 않으면 고치지 않는다.
- 작업 파일은 대상 프로젝트의 `.product-planning/{기능}/` 임시 폴더에만 둔다. git에 올라가지 않고 내보내면 지워진다. 메모리나 다른 프로젝트 파일에 남기지 않는다. 남는 것은 마지막에 내보내는 결과물뿐이다.

## 2. 시작

1. 영어 기능 이름을 정한다. 요청이 이미 영어 이름이면 그것을 쓰고, 아니면 입력창으로 후보를 묻는다.
2. 대상 프로젝트에 `docs/product/{기능}/`가 이미 있으면, 고치는 것인지 입력창으로 묻는다. 고치면 `pp.mjs import <프로젝트> <프로젝트>/.product-planning/{기능}`으로 읽어 오고, 고칠 문서만 `상태: 작성중`으로 돌린다.
3. 없으면 `pp.mjs init <프로젝트>/.product-planning/{기능} <기능 한국어 이름>`으로 `brief.md` 틀을 만든다. 작업 폴더가 이미 있으면 그대로 잇는다.
4. `pp.mjs check <폴더>`로 지금 단계를 확인하고 그 단계 작성법을 읽은 뒤 첫 질문을 한다.

## 3. 매 답의 루프

1. 사람이 답한다.
2. 답을 그 단계 파일(`brief.md`·`plan.md`·`spec.md`)의 해당 칸에 옮긴다.
3. `pp.mjs check <폴더>`를 돌린다.
4. 보고의 "추가되어야 완성" 가운데 사람 답이 필요한 것을 원문 인용 질문 1~3개로 바꿔 `AskUserQuestion`으로 묻는다.
5. 번호 순서, 머리 이름, 표 모양처럼 형식만 틀린 것은 묻지 않고 고친 뒤 3으로 돌아간다.
6. 보고가 `잠금 전`을 내면 요구사항 전체(BR, 범위 밖, 페르소나, 요구사항, 완성 기준)를 보여 주고 잠가도 되는지 입력창으로 묻는다. 사람이 맞다고 하면 `pp.mjs lock <폴더>`. `잠근 뒤 바뀜`이면 무엇이 바뀌었는지 보여 주고, 맞으면 `unlock` 뒤 다시 `lock`, 아니면 되돌린다.
7. 보고가 `기획 없음`, `기획 상세 스펙 없음`을 내면 `pp.mjs init <폴더>`로 다음 틀을 만들고, 단계가 바뀌었다고 한 줄로 알린 뒤 그 단계 첫 질문을 한다.

매 바퀴 보여 주는 것은 하네스 보고의 `단계`·`추가되어야 완성` 줄과 질문뿐이다. 이미 한 일이나 규칙 설명은 되풀이하지 않는다.

## 4. 질문은 원문을 인용해 입력창으로 한다

모든 질문은 `AskUserQuestion`으로 하고, 질문 문장 앞에 어디서 나온 질문인지 붙인다 ([설계서](../../docs/design.md) 4장).

```text
header: BR1 페르소나
question: |
  근거  비즈니스 요구사항 › BR1
  원문  "작성자는 다시 올리지 않고 글을 고칠 수 있어야 한다"
  글을 고치고 싶어 하는 사람은 주로 어떤 사람인가요?
options:
  - 하루에 여러 번 소식을 올리는 사람 (추천) — 원문의 "작성자"와 문의 근거에서
  - 가끔 긴 글을 쓰는 사람
```

- 원문은 고치거나 줄이지 않는다. 1단계처럼 앞선 문서가 없으면 사람이 방금 한 말을 원문으로 쓴다.
- 한 번에 질문 1~3개, 질문마다 선택지 2~4개. 추천은 첫 선택지에 `(추천)`과 이유 한 줄.
- 답 후보는 사람이 이미 한 말과 기획 문서에 있는 내용에서만 만든다.
- 흐름 분기를 물을 때는 선택지마다 `preview`에 그 답을 고르면 흐름가 어떻게 되는지 md 조각을 넣는다.
- 여러 개를 같이 고를 수 있으면 `multiSelect`를 켠다. Other에 되묻는 말이 오면 텍스트로 답하고 같은 질문을 다시 띄운다.

## 5. 단계마다 묻는 법

| 단계 | 인용할 원문 | 묻는 것 |
|---|---|---|
| 1-2 왜 지금 | 사람의 말 | 지금 무엇이 문제이고 근거(숫자, 출처)는 무엇인가 |
| 1-3 목표 | 왜 지금 | 무엇이 되면 성공인가, 숫자로 몇인가 |
| 1-4 BR | 목표 | 그러려면 사업 입장에서 무엇이 꼭 돼야 하나 |
| 1-5 범위 | BR | 이번에 하지 않을 것, 기한·정책·법 |
| 2-1 페르소나 | BR | 누가, 무엇을 원하고, 평소 어떻게 행동하나 |
| 2-2 요구사항 | BR, 원하는 것 | 이 사람에게 무엇을 해 줘야 하나 |
| 2-3 우선순위 | 요구사항 | 이것만 먼저 나가도 쓸 만한가 |
| 2-4 완성 기준 | 요구사항 | 어떤 모습을 보면 다 됐다고 할 수 있나 |
| 3 PRD 확정 | 정할 것 | 남은 것, 그리고 PRD 미리 보기 확인 |
| 4-1~4-4 상태·조건·단위·흐름 | 요구사항, 완성 기준, 상태표, 조건표 | 거치는 상태, 갈리는 곳과 갈래, 갈래마다 결과, 실패할 때 |

- 해결 방법(화면, 단추, 기술)은 1~3단계에서 적지 않고 "그걸로 무엇을 얻고 싶으신가요?"로 되묻는다. 화면 흐름은 4단계에서 다룬다.
- 페르소나는 겉모습보다 사용 상황과 습관을 묻는다. 모르면 `(가정)`을 붙이고 정할 것에 남긴다.
- PRD 확정 전에는 `brief.md`와 `plan.md`를 합친 모습(설계서 2장 순서)을 보여 주고 확정을 받는다.
- 흐름은 시작, 기본 흐름, 대안 흐름, 예외 흐름 순서로 묻는다. 기본 흐름 단계마다 "여기서 다르게 되는 경우는?", "실패하면?"을 묻고, 상태표의 모든 상태를 하나씩 짚는다.
- 기획 상세 스펙에는 화살표, 굵게, 이모지 같은 기호를 쓰지 않는다. 번호와 낱말만 쓴다.
- 같은 흐름이 두 번 나오면 함수(`FN`)로 뺄지 묻는다.

## 6. 요구사항 대조 (4-5)

1. `pp.mjs sheet <폴더>`로 검토지를 받는다.
2. 완성 기준마다 그것을 만족하는 줄을 검토지의 `lines`에서 찾는다. 줄 경로는 한 글자도 바꾸지 않고 옮긴다.
3. 찾으면 `met`과 근거 줄, 못 찾으면 `missing`과 "무엇이 추가돼야 완성인지" 한 문장을 `trace.json`에 쓴다.
4. 근거가 애매하면 `missing`으로 두고 사람에게 묻는다. `missing`을 채우려고 흐름를 직접 고치지 않는다.
5. 하네스가 `대조 낡음`을 내면 그 기준만 다시 대조한다.

## 7. 대화 중에 바뀌는 것

- 새 요구사항이 나오면 그 요구사항만 추가하고, 근거 BR이 없으면 1단계로 돌아가 묻는다.
- 확정한 문서를 바꾸면 그 문서를 `상태: 작성중`으로 돌리고 다시 확정받는다.
- "이건 이번에 안 한다"면 완성 기준에 `[제외: 사유]`를 붙여 남긴다.

## 8. 끝

- 보고 단계가 `기획 완료`가 되면 기획이 끝난 것이다. 요구사항·완성 기준·피쳐 수를 한 줄로 알린다.
- "이어서 개발 스펙을 같이 쓸까요?"를 입력창으로 묻는다. 원하면 `/yw-dev <기능>`의 절차로 이어 간다.
- 기획만 남기려면 `pp.mjs export <폴더>`로 `docs/product/{기능}/prd.md`·`spec.md`를 낸다. 파일이 있으면 덮어쓸지 먼저 묻고 `--force`를 붙인다. 작업 폴더는 개발을 위해 남는다.
- 그만두겠다고 하면 `pp.mjs discard <폴더>`로 작업 폴더를 지울지 입력창으로 묻는다.
