# SDD 스펙 같이 쓰기

폴더: $ARGUMENTS

폴더가 이름만이면 `~/.product-planning/work/{이름}/`으로 읽는다. 비어 있으면 그 아래 폴더 목록을 입력창 선택지로 보여 주고 고르게 한다.

- 작성법: 이 스킬 폴더 기준 `../../docs/sdd-guide.md` — 시작할 때 한 번 읽는다
- 하네스: `node <플러그인 루트>/scripts/pp.mjs` (플러그인 루트 = 이 스킬 폴더의 두 단계 위)
- 대조 파일 모양과 보고 모양: `../../docs/harness.md` 3·4장

## 1. 지켜야 할 것

- 트리는 사람이 분기마다 답한 것만 옮긴다. 답이 없는 가지를 추측해서 채우지 않는다.
- 상태·조건은 표에 먼저 쓰고, 트리는 표의 이름을 그대로 부른다.
- 트리를 쓰다가 표에 없는 상태나 조건이 나오면 트리에 쓰기 전에 표에 넣을지 묻는다.
- 답이 PRD와 어긋나면 SDD에 쓰지 않고 PRD를 고칠지 먼저 묻는다. 고치면 `/yw-plan`의 절차로 돌아간다. 요구사항이면 `unlock`부터 한다.
- 기술 컨벤션·코드 규칙은 다루지 않는다.
- `상태: 확정`은 사람이 확정한다고 말했을 때만 바꾼다.
- 스펙 내용을 메모리나 프로젝트 파일에 남기지 않는다. 프로젝트에 남는 것은 내보낸 `{feature}/` 폴더의 문서뿐이다.

## 2. 시작

1. `pp.mjs check <폴더>`를 돌린다. 단계가 요구사항이나 PRD면 PRD부터 확정해야 한다고 알리고 `/yw-plan`의 절차로 간다.
2. `sdd.md`가 없으면 `pp.mjs init <폴더> <기능 이름>`으로 틀을 만든다.
3. 지금 단계의 첫 질문을 한다.

## 3. 매 답의 루프

1. 사람이 답한다.
2. 답을 `sdd.md`의 표나 트리에 옮기고, 진행표의 그 단위를 `작성중`으로 둔다.
3. `pp.mjs check <폴더>`를 돌린다.
4. 보고의 "추가되어야 완성" 가운데 사람 답이 필요한 것을 질문 1~3개로 바꿔 `AskUserQuestion` 입력창으로 묻는다.
5. 표 모양이나 들여쓰기처럼 형식만 틀린 것은 묻지 않고 고친 뒤 3으로 돌아간다.
6. 한 단위에 걸린 것이 없으면 진행표를 `완료`로 바꾸고, 다음 `대기` 단위를 알리고 첫 질문을 한다.

매 바퀴 보여 주는 것은 하네스 보고의 `단계`·`완성도`·`추가되어야 완성` 줄과 질문뿐이다.

## 4. 단계마다 묻는 법

| 단계 | 묻는 것 | 예 |
|---|---|---|
| 상태 수립 | 대상마다 거치는 상태와 뜻 | "게시글은 올린 뒤에 어떤 상태가 될 수 있나요?" |
| 조건 수립 | 흐름이 갈리는 곳과 갈래, 무엇으로 정해지는지 | "수정 단추는 누구에게 보여야 하나요?" |
| 단위 나누기 | 요구사항을 어떤 피쳐로 묶을지, 반복되는 흐름이 있는지 | "닫기 확인은 다른 화면에서도 똑같이 쓰나요?" |
| 단위별 트리 | 진입한 뒤 첫 분기, 갈래마다 결과 | "권한이 없으면 수정 단추는 숨기나요, 비활성인가요?" |
| 요구사항 대조 | 빠졌다고 나온 완성 기준을 어떻게 채울지 | "R1-2 댓글이 남는다는 게 어느 순간에 보여야 하나요?" |
| 확정 | 전체 확인 | "모든 완성 기준이 트리와 이어졌어요. 확정할까요?" |

- 트리는 위에서 아래로, 진입 → 분기 → 갈래 → 결과 순서로 한 갈래씩 묻는다.
- 상태 분기에서는 상태표의 모든 상태를 하나씩 짚어 묻는다. "잠김일 때는요?"
- 같은 흐름이 두 번 나오면 함수로 뺄지 묻는다.

## 4.1 질문은 입력창으로 한다

모든 질문은 텍스트로 쓰지 않고 `AskUserQuestion` 도구로 한다. 텍스트로 늘어놓은 질문은 읽기 어렵다.

- 한 번에 질문 1~3개, 질문마다 선택지 2~4개를 준다. 사람은 고르거나 "Other"에 직접 쓴다.
- `header`는 단위 이름이나 걸린 종류로 짧게 쓴다. 예: `잠김일 때`, `빠진 갈래`
- 추천이 있으면 첫 선택지로 두고 이름 끝에 `(추천)`, 설명에 이유 한 줄을 쓴다.
- 트리 분기를 물을 때는 선택지마다 `preview`에 그 답을 고르면 트리가 어떻게 되는지 md 조각을 넣는다.
- 상태·조건 후보는 상태표·조건표와 기획에 있는 것에서만 만든다. 새 사실을 지어낸 후보는 주지 않는다.
- 사람이 Other에 되묻는 말을 쓰면, 먼저 텍스트로 답하고 같은 질문을 다시 입력창으로 띄운다.

```text
header: 잠김일 때
question: 게시글이 잠김이면 [수정] 단추는 어떻게 보이나요?
options:
  - 비활성 + 안내 (추천) — 왜 못 고치는지 알 수 있어서
    preview: - **잠김**\n  - → [수정] 단추가 비활성이다\n  - → 단추에 "잠긴 글은 수정할 수 없어요"가 뜬다
  - 숨김 — 권한 없음과 같게 둔다
    preview: - **잠김**\n  - → [수정] 단추가 보이지 않는다
```

## 5. 요구사항 대조

형식 검사가 0건이 되면 하네스가 대조 단계로 넘긴다.

1. `pp.mjs sheet <폴더> --save`로 검토지를 작업 폴더의 `sheet.json`에 받는다. 출력이 길면 이 파일을 읽는다.
2. 완성 기준마다 그것을 만족하는 줄을 검토지의 `lines`에서 찾는다. 줄 경로는 한 글자도 바꾸지 않고 옮긴다. 조건이 무엇으로 정해지는지가 기준이면 `조건표 ›` 줄을 쓴다.
3. 찾으면 `met`과 근거 줄, 못 찾으면 `missing`과 "무엇이 추가돼야 완성인지" 한 문장을 `trace.json`에 쓴다.
4. 근거가 애매하면 `met`으로 두지 않고 `missing`으로 두고 사람에게 묻는다.
5. `missing`을 채우려고 트리를 직접 고치지 않는다. 사람에게 묻고, 답을 트리에 옮긴 뒤 대조를 다시 한다.
6. 하네스가 `대조 낡음`을 내면 그 기준만 다시 대조한다.

## 6. 끝

- 하네스 단계가 `완료`이고 종료 코드가 0이면 결과물을 내보낸다.
- `pp.mjs export <폴더> <문서 폴더>`로 `{문서 폴더}/{feature}/sdd.md`를 쓴다. PRD를 낸 문서 폴더와 같은 곳을 쓴다.
- 앞서 낸 `prd.md`와 내용이 같으면 그대로 두고, 아직 없으면 함께 쓴다. 내용이 다른 파일이 있으면 덮어쓸지 먼저 묻고 `--force`를 붙인다.
- 다 쓰면 작업 폴더는 지워진다. 작업 폴더에 하네스 파일이 아닌 것이 있으면 멈추니, 그 파일을 치우거나 `--keep`을 붙인다. 쓴 경로를 한 줄로 알린다.
