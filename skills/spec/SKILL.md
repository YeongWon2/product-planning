# 기획서 파이프라인

이 스킬은 기획을 **요소와 관계로 이루어진 모델**(`spec.json`)로 만들고, 규칙으로 검사해, 같은 모양의 HTML로 빌드한다. 사람이 고치는 파일은 `spec.json` 하나뿐이다.

- 형식 계약: 이 스킬 폴더 기준 `../../docs/산출물-명세.md` — `spec.json`을 쓰기 전에 §2를 읽는다
- 설계 배경: `../../docs/설계서.md` — 단계(§4), 흐름 규칙(§4.1), 검토 기준(§5)이 필요할 때만 읽는다
- 명령: `node <플러그인 루트>/scripts/spec.mjs check|build <spec.json>` (플러그인 루트 = 이 스킬 폴더의 두 단계 위)

## 1. 입구 고르기

| 사용자가 가진 것 | 입구 | 시작점 |
|---|---|---|
| 아이디어나 요청만 | 새로 만들기 | 단계 1 정의부터 인터뷰 |
| 기획 문서·디자인 메모·티켓 같은 기존 자료 | 보완하기 | 자료를 읽고 사실을 요소로 옮긴 뒤 빈 곳만 인터뷰 |
| 이미 있는 `spec.json` + 바꿀 내용 | 변경하기 | 바꿀 요소와 영향받는 요소만 다룬다 |

`spec.json` 위치를 사용자가 정하지 않았으면 `specs/{기능 이름}/spec.json`으로 제안한다.

## 2. 인터뷰 순서

설계서 §4 단계를 따른다. 한 번에 질문은 1~3개만 한다. 앞 단계가 비면 다음 단계로 넘어가지 않는다.

1. **정의**: 해결할 문제와 그 근거, 누구를 위한 것인지, 목표 지표, 이번에 하지 않는 것
2. **시나리오**: 요구사항 한 줄씩 ("누가 무엇을 한다"), 요구사항마다 단계 (누가, 어느 앱에서, 어떤 동작)
3. **모델링**: 개체와 상태·전이, 동작 (종류 `list`·`view`·`create`·`update`·`delete`·`other`, 입력 항목과 검증 규칙, 되돌릴 수 있는지, 다른 앱 영향), 동작 가능표의 칸

## 3. 쓰지 않는 것

아래는 도구가 파생하므로 `spec.json`에 적지 않는다. 적으면 한 사실이 두 곳에 생긴다.

- 화면, 화면 이동, 모달·확인 창 — 흐름 규칙 F1~F11이 만든다. 사용자가 판단을 바꾸고 싶으면 `flowOverrides`와 `decisions`에 적는다
- 완료 조건 초안 — 동작 가능표와 상태 전이에서 나온다. 사람이 확정한 것만 `acceptance`에 적는다
- 동작 가능표 빈칸에서 나오는 질문

## 4. 사실을 지어내지 않는다

- 모든 사실에는 `source`를 단다. 사용자가 말했거나 문서에서 읽은 것은 `doc`·`data` 등과 위치(`ref`), 근거가 없으면 `{ "kind": "assumption" }`.
- 모르는 것은 채우지 않고 `questions`에 넣는다. 담당자(`owner`)와 착수를 막는지(`blocking`)를 함께 적는다.
- 동작 가능표 칸을 추측으로 채우지 않는다. 비워 두면 검사가 정할 것으로 올린다.
- 보완하기에서 두 자료가 서로 다르게 말하면 한쪽을 고르지 않고 `questions`에 충돌로 올린다.

## 5. 검사 루프

1. `check`를 돌린다. 종료 코드 0 = 착수 가능, 1 = 착수 불가, 2·3 = 입력·경로 오류.
2. 차단 이슈를 사람의 말로 풀어 설명한다. 사람이 답해야 하는 것은 질문으로 바꾼다.
3. 답을 받아 `spec.json`을 고치고 다시 `check`를 돌린다.
4. 이렇게 되면 멈추고 보고한다: 착수 가능이 됐다 / 한 번 돌았는데 차단 이슈 수가 줄지 않았다 / 남은 이슈가 모두 사람의 결정이 필요하다 / 3회를 돌았다.

## 6. 빌드와 전달

- `build`로 `out/{폴더 이름}.html`과 `out/report.json`을 만들고 경로를 알려 준다.
- 보고에는 착수 가능 여부, 차단 이슈 수, 착수를 막는 정할 것 목록을 넣는다.
- 디자인 도구·문서 도구·이슈 트래커로 옮기는 것은 사용자가 대상을 정하고 확인한 뒤에만 한다. 옮길 내용은 HTML 안의 `<script type="application/json" id="spec-model">` 모델 데이터에서 읽는다 (설계서 §9).
